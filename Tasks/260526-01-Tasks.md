# [해결] 0526 포션 F 스프라이트 회전 분리 이슈

작성일: 2026-05-26

# 현재 상황

포션 오브젝트에 표시되는 F 키 스프라이트가 포션과 함께 이동할 뿐 아니라, 포션의 물리 회전까지 그대로 따라 회전하고 있다.

원하는 동작은 다음과 같다.

- F 키 스프라이트는 포션의 월드 좌표 아래쪽에 계속 붙어 이동한다.
- 포션이 회전하더라도 F 키 스프라이트 자체는 회전하지 않는다.
- 플레이어가 포션 범위에 들어오고 나갈 때 기존처럼 표시/숨김 처리는 유지한다.

---

# 현재 구조

## 1. 포션 프리팹 구조

`Assets/Prefab/Potion.prefab`에서 `F Sprite`는 `Potion` 오브젝트의 자식으로 배치되어 있다.

현재 `F Sprite`의 로컬 위치는 대략 다음과 같다.

```text
localPosition: (0, -0.94, 0)
localRotation: identity
parent: Potion
```

이 구조에서는 부모인 `Potion` Transform이 회전하면 자식인 `F Sprite`도 같은 회전을 상속받는다.

## 2. 포션 스크립트

`Assets/Scripts/Actors/RelicSystem/Potion.cs`는 `Fsprite`를 참조하고, 플레이어가 트리거 범위에 들어오거나 나갈 때 활성 상태만 바꾼다.

현재 흐름은 다음과 같다.

- `Start()`에서 `Fsprite.SetActive(false)`로 숨긴다.
- `OnTriggerEnter2D()`에서 플레이어가 들어오면 `Fsprite.SetActive(true)`로 표시한다.
- `OnTriggerExit2D()`에서 플레이어가 나가면 `Fsprite.SetActive(false)`로 숨긴다.
- 위치나 회전은 별도로 보정하지 않는다.

## 3. 포션 생성 및 물리 회전

`Assets/Scripts/Actors/RelicSystem/Relic/KnightHealerPotion.cs`는 포션을 생성한 뒤 `Rigidbody2D`에 힘과 토크를 준다.

현재 흐름은 다음과 같다.

- `Instantiate(potionPrefab, transform.position, Quaternion.identity)`로 포션을 생성한다.
- `Rigidbody2D.AddForce(...)`로 포션을 튕기듯 이동시킨다.
- `Rigidbody2D.AddTorque(...)`로 포션에 회전력을 준다.

따라서 포션 루트 Transform이 물리적으로 회전하고, 자식인 `F Sprite`도 그 회전을 그대로 상속받는다.

---

# 원인 정리

직접적인 원인은 `F Sprite`가 포션의 자식 오브젝트인데, 회전 상속을 막는 보정 로직이 없다는 점이다.

현재 구조에서는 `F Sprite`의 로컬 회전을 `identity`로 두어도 부모가 회전하면 월드 회전은 함께 변한다. 즉, `F Sprite`가 포션 아래에 붙어 있는 것은 자연스럽지만, 포션의 회전까지 따라가는 것도 Unity Transform 계층 구조상 자연스러운 결과다.

# 예상 해결 방안

## 1. 권장안: 자식 구조는 유지하고 월드 위치/회전만 보정

`F Sprite`를 포션의 자식으로 계속 유지하되, `Potion.cs`에서 표시 중일 때 매 프레임 월드 기준 위치와 회전을 보정한다.

권장 동작은 다음과 같다.

- 위치는 `transform.position + worldOffset` 기준으로 계산한다.
- `worldOffset`은 기존 프리팹의 아래쪽 위치를 유지하기 위해 기본값을 `(0, -0.94, 0)` 정도로 둔다.
- 회전은 `Quaternion.identity` 또는 별도 지정한 고정 회전으로 유지한다.
- 플레이어가 범위에 들어와 F 스프라이트를 켤 때 즉시 한 번 보정한다.
- 표시 중에는 `LateUpdate()`에서 계속 보정한다.

예상 구현 형태는 다음과 같다.

```csharp
public class Potion : MonoBehaviour
{
    public GameObject Fsprite;
    public float value;

    [SerializeField]
    private Vector3 fSpriteWorldOffset = new Vector3(0f, -0.94f, 0f);

    private void Start()
    {
        Fsprite.SetActive(false);
    }

    private void LateUpdate()
    {
        if (Fsprite.activeSelf)
        {
            UpdateFSpriteTransform();
        }
    }

    private void ShowFSprite()
    {
        UpdateFSpriteTransform();
        Fsprite.SetActive(true);
    }

    private void HideFSprite()
    {
        Fsprite.SetActive(false);
    }

    private void UpdateFSpriteTransform()
    {
        Fsprite.transform.position = transform.position + fSpriteWorldOffset;
        Fsprite.transform.rotation = Quaternion.identity;
    }
}
```

이 방식은 프리팹 계층을 크게 바꾸지 않아도 되고, 기존 `Fsprite` 참조와 표시/숨김 흐름을 그대로 사용할 수 있다.

## 2. 대안: F 스프라이트를 별도 월드 오브젝트로 분리

`F Sprite`를 포션의 자식이 아닌 별도 오브젝트로 생성하거나 배치하고, 포션을 따라가도록 만드는 방법도 있다.

다만 이 경우 다음 처리가 추가로 필요하다.

- 포션이 파괴될 때 F 스프라이트도 함께 정리해야 한다.
- 프리팹 참조 또는 런타임 생성 참조를 별도로 관리해야 한다.
- 현재 단순한 표시용 스프라이트에는 구조 변경 비용이 더 크다.

따라서 1차 수정에서는 권장하지 않는다.

---

# 구현 시 주의점

- `OnTriggerStay2D()`는 현재 플레이어 태그 확인 없이 F 키 입력 시 `Apply()`를 호출하므로, 이번 회전 문제와는 별개로 잠재적인 동작 범위 확인이 필요할 수 있다.
- F 스프라이트의 위치 보정은 물리 업데이트 이후 화면에 반영되도록 `LateUpdate()`에서 수행하는 것이 자연스럽다.
- 프리팹의 기존 `F Sprite` 로컬 위치가 시각적으로 적절하므로, 월드 오프셋 기본값은 기존 로컬 위치를 기준으로 잡는 것이 좋다.
- 포션 오브젝트가 파괴될 때 자식 `F Sprite`도 함께 파괴되는 현재 수명 구조는 유지된다.

# 검증 방향

수정 후 다음 항목을 확인한다.

1. 포션이 생성되어 튕기고 회전할 때 F 스프라이트가 포션 아래 월드 위치를 따라 이동한다.
2. 포션이 회전해도 F 스프라이트 자체는 회전하지 않는다.
3. 플레이어가 포션 범위에 들어오면 F 스프라이트가 표시된다.
4. 플레이어가 포션 범위에서 나가면 F 스프라이트가 숨겨진다.
5. F 키 입력 시 포션 사용, 회복, 사운드 재생, 포션 파괴 동작이 기존과 동일하게 동작한다.

# 결론

현재 문제는 포션의 물리 회전이 자식 `F Sprite`에 그대로 상속되면서 발생한다.

가장 작은 수정으로 해결하려면 `Potion.cs`에서 F 스프라이트가 활성화되어 있는 동안 월드 위치는 포션 아래로 갱신하고, 월드 회전은 고정되도록 보정하면 된다. 이렇게 하면 포션의 이동은 따라가되 회전은 따라가지 않는 원하는 동작을 만들 수 있다.

# 해결 보고서

## 1. 적용 내용

`Assets/Scripts/Actors/RelicSystem/Potion.cs`에 권장안 1번을 적용했다.

수정 내용은 다음과 같다.

- `fSpriteWorldOffset` 직렬화 필드를 추가해 F 스프라이트의 월드 기준 아래쪽 오프셋을 조정할 수 있게 했다.
- `ShowFSprite()`에서 F 스프라이트를 켜기 전에 위치와 회전을 즉시 보정하도록 했다.
- `LateUpdate()`에서 F 스프라이트가 활성화되어 있을 때 매 프레임 월드 Transform을 보정하도록 했다.
- `UpdateFSpriteTransform()`에서 F 스프라이트 위치는 `transform.position + fSpriteWorldOffset`으로 맞추고, 회전은 `Quaternion.identity`로 고정했다.
- `HideFSprite()`를 추가해 기존 숨김 처리를 유지하면서 null 참조 방어를 넣었다.

## 2. 변경 후 동작

포션 프리팹의 자식 구조는 그대로 유지된다.

다만 F 스프라이트가 표시되는 동안에는 매 프레임 월드 위치와 회전이 다시 지정되므로, 포션의 이동은 따라가지만 포션의 물리 회전은 따라가지 않는다.

즉, 포션이 `Rigidbody2D.AddTorque()`로 회전하더라도 F 스프라이트는 항상 화면 기준 정방향 상태를 유지하고, 포션의 월드 좌표 아래쪽으로만 이동한다.
