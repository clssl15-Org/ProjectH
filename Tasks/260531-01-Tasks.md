# [확인/설계] 0531 Stage2 2-3/2-10 포탈 미출현 원인 및 수정 방향

# 범위

Stage2 일반 소형맵 중 `Stage2 3`과 `Stage2 10`에서 전투 종료 후 포탈이 나오지 않는 현상을 확인하고, 수정 방향을 정리한다.

대상 씬:

- `Assets/Scenes/Stage2/Stage2 3.unity`
- `Assets/Scenes/Stage2/Stage2 10.unity`

관련 코드:

- `Assets/Scripts/Actors/Spawner/SpawnManager.cs`
- `Assets/Scripts/Actors/Spawner/MonsterSpawner.cs`
- `Assets/Scripts/Game/Stage/ClearObjectsActivator.cs`
- `Assets/Scripts/Game/Stage/LevelManager.cs`

# 확인 내용

두 씬 모두 포탈 프리팹이나 `ClearObjects` 자체가 빠진 상태는 아니다.

- `Stage2 3.unity`에는 `ClearObjects`가 존재한다.
  - 위치: `(17.97, -9.64, 0)`
  - `ClearObjects.prefab` 안에 `Portal`과 `Box`가 포함되어 있다.
- `Stage2 10.unity`에도 `ClearObjects`가 존재한다.
  - 위치: `(17.06, -8.67, 0)`
  - 동일하게 `ClearObjects.prefab` 안에 `Portal`과 `Box`가 포함되어 있다.

따라서 현재 증상은 "포탈 오브젝트가 씬에 없다"보다는 "클리어 오브젝트 활성화 경로가 호출되지 않는다"에 가깝다.

---

# 현재 클리어 흐름

일반 스테이지의 클리어 흐름은 다음과 같다.

1. 각 `MonsterSpawner`가 자신이 관리하는 모든 페이즈를 끝낸다.
2. `MonsterSpawner.OnAllPhasesComplete()`에서 `IsAllPhasesComplete = true`로 바꾼다.
3. 해당 스포너가 `LevelManager.Instance.SpawnManager.CheckAllSpawnersComplete()`를 호출한다.
4. `SpawnManager.CheckAllSpawnersComplete()`는 `SpawnerList`에 등록된 모든 스포너의 `IsAllPhasesComplete`를 확인한다.
5. 모든 스포너가 완료 상태이면 `OnAllMonstersCleared()`를 호출한다.
6. `OnAllMonstersCleared()`가 `ClearObjectsActivator.ActivateRootAndChildren(clearObject)`를 호출해서 `ClearObjects`와 자식 포탈/상자를 켠다.

핵심 조건:

```csharp
foreach (var spawner in SpawnerList)
{
    if (!spawner.IsAllPhasesComplete)
    {
        return;
    }
}
```

즉, `SpawnerList` 안의 스포너 중 하나라도 완료 상태가 아니면 포탈이 나오지 않는다.

# 의심 원인

`Stage2 3`과 `Stage2 10`은 모두 복수의 `MonsterSpawner`를 가진다.

`Stage2 3`:

- `Monster Spawner_Stage1`
- `Monster Spawner_Stage1 (1)`

`Stage2 10`:

- `Monster Spawner_Stage1`
- `Monster Spawner_Stage1 (1)`
- `Monster Spawner_Stage1 (2)`

이 구조에서는 플레이어가 화면상 적을 다 잡은 것처럼 보여도, 등록된 스포너 중 하나가 `IsAllPhasesComplete == false`로 남아 있으면 `ClearObjects` 활성화가 영구히 막힌다.

특히 다음 상태가 문제를 만들 수 있다.

- 스포너가 등록은 됐지만 페이즈 시작/완료까지 가지 못한 경우
- 페이즈 설정이 비어 있거나 런타임 페이즈가 0개인데 완료 처리 없이 에러만 남기는 경우
- 스포너가 비활성/파괴/불완전한 상태인데 `SpawnerList`에 남아 클리어 조건을 막는 경우
- 특정 스포너의 몬스터 사망 이벤트가 누락되어 `activeMonsters.Count == 0`까지 가지 못하는 경우

---

# 수정 방향

1차 수정은 씬에서 포탈을 직접 켜거나 위치만 바꾸는 방식이 아니라, 스포너 완료 판정 경로를 보강하는 방향으로 진행한다.

## 1. 미완료 스포너 로그 추가

`SpawnManager.CheckAllSpawnersComplete()`에서 완료되지 않은 스포너 이름을 로그로 남긴다.

목적:

- `Stage2 3`, `Stage2 10`에서 어떤 스포너가 false로 남는지 즉시 확인한다.
- 이후 씬 데이터 문제인지 코드 흐름 문제인지 분리한다.

예상 로그 정보:

- 현재 씬 이름
- 전체 등록 스포너 수
- 미완료 스포너 이름
- 각 스포너의 `IsAllPhasesComplete`

## 2. 유효하지 않은 스포너 정리

`SpawnManager.CheckAllSpawnersComplete()`에서 null 또는 더 이상 유효하지 않은 스포너가 클리어를 막지 않도록 `SpawnerList`를 정리한다.

예상 처리:

- `SpawnerList.RemoveAll(spawner => spawner == null)` 형태로 null 제거
- 필요하면 비활성 스포너를 클리어 조건에서 제외할지 검토

주의:

- 비활성 스포너 제외는 씬 설계와 충돌할 수 있으므로, 로그로 실제 상태를 확인한 뒤 적용한다.

## 3. 완료 불가능 스포너 방어

`MonsterSpawner.StartSpawner()`에서 다음 상태가 발생하면 `IsAllPhasesComplete`가 false로 영구 고정되지 않게 처리한다.

- `phases == null`
- `phases.Count == 0`
- `BuildRuntimePhases()` 이후 `runtimePhases.Count == 0`

예상 처리 방향:

- 경고 로그를 남긴다.
- 해당 스포너를 완료 처리하고 `CheckAllSpawnersComplete()`를 호출한다.

의도:

- 잘못 배치된 빈 스포너 하나가 포탈 출현 전체를 막지 않게 한다.

## 4. 필요 시 씬 데이터 정리

로그 확인 결과 특정 씬의 특정 스포너가 불필요하거나 잘못 설정된 것으로 확인되면 씬 데이터를 정리한다.

가능한 정리:

- 불필요한 `MonsterSpawner` 제거
- 비어 있는 페이즈 제거
- 누락된 스폰 포인트/몬스터 풀 수정
- 실제 전투 구역과 맞지 않는 스포너 배치 수정

# 검증 항목

Unity Editor에서 다음을 확인한다.

- `Stage2 3`에서 모든 적 처치 후 `ClearObjects`가 활성화된다.

# 추가 적용: 완료 판정 안전망

사용자 요청에 따라 다음 두 가지를 모두 적용한다.

## 1. `ClearObjects` 활성화 재진입 방지

`CheckAllSpawnersComplete()`는 완료 이벤트와 주기 감시 양쪽에서 호출될 수 있으므로, 모든 스포너가 완료된 뒤 `ClearObjects` 활성화가 반복 실행되지 않도록 `clearObjectsActivated` 플래그를 둔다.

목표:

- 포탈/상자 활성화가 한 번만 실행된다.
- 10프레임 감시가 켜져 있어도 이미 클리어된 스테이지에서는 추가 처리를 하지 않는다.
- `Clear()`나 새 씬의 `ClearObjects` 재바인딩 시 플래그를 초기화한다.

## 2. 10프레임 단위 완료 감시

완료 이벤트가 누락되거나 호출 순서 문제로 `CheckAllSpawnersComplete()`가 마지막에 한 번 더 호출되지 않는 경우를 대비해, `SpawnManager.Update()`에서 10프레임마다 완료 상태를 다시 확인한다.

처리 원칙:

- `SpawnerList`가 비어 있거나 이미 `ClearObjects`가 활성화된 경우에는 검사하지 않는다.
- 감시 루프에서는 미완료 스포너 로그를 반복 출력하지 않는다.
- 기존 이벤트 기반 호출은 유지해 즉시 클리어 처리가 가능하게 한다.
- 마지막 스포너 등록 직후 10프레임 동안은 추가 등록 가능성을 열어 두고 활성화를 확정하지 않는다.
- `clearObject` 참조가 비어 있으면 `ClearObjects`를 다시 찾고, 그래도 없을 때는 경고를 한 번만 남긴다.

검증 항목:

- `Stage2 3`에서 마지막 적 처치 후 포탈/상자가 한 번만 활성화된다.
- `Stage2 10`에서 마지막 적 처치 후 포탈/상자가 한 번만 활성화된다.
- 완료 이벤트가 늦거나 누락되어도 10프레임 감시가 클리어 상태를 복구한다.
- 클리어 후 콘솔에 동일한 활성화/미완료 로그가 프레임마다 반복되지 않는다.

# 추가 적용: 스포너 내부 몬스터 생존 감시

사용자 요청에 따라 `MonsterSpawner`가 사망 콜백에만 의존하지 않고, 0.5초 간격으로 자신이 등록한 몬스터 목록을 직접 점검하도록 보강한다.

## 배경

현재 `MonsterSpawner`는 스폰한 몬스터를 `activeMonsters`에 등록하고, 몬스터의 `ConditionChanged` 콜백에서 `Dying` 또는 `Died` 이벤트를 받으면 목록에서 제거한다. 이 콜백이 누락되거나 호출 순서가 꼬이면 `activeMonsters`에 이미 죽은 몬스터가 남아 다음 페이즈 또는 전체 완료 판정이 막힐 수 있다.

## 적용 방향

- 기존 콜백은 유지한다.
  - 즉시 반응이 가능하다.
  - 분열/소환형 몬스터가 `Dying` payload로 자식을 전달하는 흐름을 보존한다.
- `MonsterSpawner.Update()`에서 0.5초마다 `activeMonsters`를 점검한다.
- 목록 안의 몬스터가 null, 파괴됨, `IMonster` 없음, 또는 `IsAlive == false`이면 제거한다.
- 정리 후 `activeMonsters.Count == 0`이면 다음 페이즈로 넘어간다.
- 콜백과 주기 감시가 동시에 작동해도 `WaitAndStartNextPhase()`가 중복 실행되지 않도록 진행 예약 플래그를 둔다.

## 기대 효과

- 몬스터 사망 이벤트가 누락되어도 스포너가 0.5초 안에 자기 목록을 복구한다.
- 특정 스포너가 죽은 몬스터를 붙잡고 있어 `IsAllPhasesComplete`가 false로 남는 문제를 줄인다.
- `SpawnManager`의 10프레임 감시는 전체 클리어 안전망으로, `MonsterSpawner`의 0.5초 감시는 개별 페이즈 안전망으로 역할이 분리된다.
