# 현재 상태

## 1. 공통 최초도달 처리

`0525-Tasks.md`에서 정리한 수정 이후, `ScenarioManager`는 시나리오 시작 시점에 최초도달 여부를 한 번 계산한다.

현재 흐름은 다음과 같다.

1. `ScenarioManager.Start()`에서 `ResolveFirstArrival()`을 호출한다.
2. `ResolveFirstArrival()`은 `GameServices.ConsumeFirstScenarioArrival(GetArrivalKey(), this)`를 통해 현재 시나리오 키가 최초인지 확인한다.
3. 결과는 `_isFirstArrivalForCurrentRun`에 캐시된다.
4. 같은 시나리오 안에서 `IsFirstArrival`을 다시 읽어도 이 캐시값을 사용한다.

이 구조는 일반 스테이지처럼 "시나리오 진입 전 대화"와 "시나리오 안의 후속 대화"가 같은 최초도달 기준을 써도 되는 경우에는 안전하다.

하지만 보스전은 한 시나리오 안에 다음 두 성격의 대화가 함께 들어 있다.

- 보스 처치 전 대화
- 보스 처치 후 대화

따라서 보스 시나리오 전체에 하나의 `IsFirstArrival`만 쓰면, "보스전 진입 기준"과 "보스 처치 완료 기준"이 섞인다.

## 2. 1보스 현재 흐름

`Scenario_Stage1_Boss`는 현재 다음 흐름을 사용한다.

- `To_Contact`
  - `IsFirstArrival == true`이면 `Stage1_Boss_Contact` 대화를 진행한다.
  - `IsFirstArrival == false`이면 처치 전 대화를 생략하고 바로 `Battle`로 간다.
- `Battle`
  - 보스 처치 후에도 같은 `IsFirstArrival`을 다시 확인한다.
  - `IsFirstArrival == true`이면 `Stage1_Boss_Passed_1`, `Stage1_Boss_Passed_2` 대화를 순서대로 진행한다.
  - `IsFirstArrival == false`이면 처치 후 대화를 생략하고 클리어 오브젝트만 활성화한 뒤 종료한다.

문제는 1보스 전투 중 사망한 경우다.

1보스에 처음 도달해 `Stage1_Boss_Contact` 처치 전 대화를 본 뒤 전투 중 사망하면, 다시 1보스에 도달했을 때 1보스 시나리오 자체는 이미 도달한 상태가 된다.

이때 처치 전 대화가 재도달 기준으로 생략되는 것은 맞다. 하지만 아직 `Stage1_Boss_Passed_1`, `Stage1_Boss_Passed_2` 처치 후 대화를 본 적이 없다면, 첫 처치 시 해당 처치 후 대화는 출력되어야 한다.

현재 구조에서는 처치 후 대화도 같은 `IsFirstArrival == false`를 사용하므로, 처음 처치했는데도 1보스 처치 후 대화가 생략될 수 있다.

즉, 1보스도 처치 전 대화와 처치 후 대화는 서로 다른 최초 기준을 가져야 한다.

## 3. 2보스 현재 흐름

`Scenario_Stage2_Boss`는 현재 다음 흐름을 사용한다.

- `To_Contact`
  - `IsFirstArrival == true`이면 `Stage2_Boss_Contact` 대화를 진행한다.
  - `IsFirstArrival == false`이면 처치 전 대화를 생략하고 바로 `Battle`로 간다.
- `Battle`
  - 보스 처치 후에도 같은 `IsFirstArrival`을 다시 확인한다.
  - `IsFirstArrival == true`이면 `Stage2_Boss_Passed` 대화를 진행한다.
  - `IsFirstArrival == false`이면 `Stage2_Boss_Passed`를 생략하고 클리어 오브젝트만 활성화한 뒤 종료한다.

문제는 플레이어가 2보스 전투 중 사망한 경우다.

예시:

1. 2보스에 처음 도달한다.
2. `Stage2_Boss_Contact` 처치 전 대화를 본다.
3. 보스 전투 중 사망한다.
4. 다시 2보스에 도달하면 2보스 시나리오 자체는 이미 도달한 적 있으므로 재도달이다.
5. 따라서 처치 전 대화가 재도달 기준으로 생략되는 것은 맞다.
6. 하지만 아직 `Stage2_Boss_Passed` 처치 후 대화는 본 적이 없다.
7. 현재 구조에서는 처치 후 대화도 같은 `IsFirstArrival == false`를 사용하므로, 처음 처치했는데도 `Stage2_Boss_Passed`가 생략될 수 있다.

즉, 2보스의 처치 전 대화와 처치 후 대화는 서로 다른 최초 기준을 가져야 한다.

## 4. 3보스 현재 흐름

`Scenario_Stage3_Boss`는 한 시나리오 안에 다음 대화 흐름을 가진다.

- 쌍둥이 보스 처치 전
  - 최초도달: `Stage3_TwinBoss_First`
  - 재도달: `Stage3_TwinBoss_Reentry`
- 쌍둥이 보스 처치 후, 최종 보스 전
  - `Stage3_Stage3_FinalBoss`
- 최종 보스 처치 후
  - `Ending_Arrival`

현재 쌍둥이 보스 처치 전 대화는 기존 `IsFirstArrival` 기준으로 분기한다.

하지만 `Stage3_Stage3_FinalBoss`와 `Ending_Arrival`은 각각 "쌍둥이 보스를 처치한 뒤 처음 보는 대화", "최종 보스를 처치한 뒤 처음 보는 대화"에 가깝다.

따라서 3보스도 다음 기준을 분리해야 한다.

- 쌍둥이 보스 처치 전 대화: 기존 시나리오 도달 기준
- 쌍둥이 보스 처치 후 대화: 쌍둥이 보스 처치 후 기준
- 최종 보스 처치 후 대화: 최종 보스 처치 후 기준

# 요청 사항

1보스, 2보스, 3보스의 대화 기준을 다음처럼 분리한다.

## 1. 처치 전 대화

처치 전 대화는 기존 기준을 유지한다.

즉, 보스 시나리오 자체에 처음 도달했는지 여부를 기준으로 최초/재도달 대화를 결정한다.

예시:

- 1보스 전투 중 사망한 뒤 다시 1보스에 도달하면, 처치 전 대화는 재도달 기준으로 처리한다.
- 2보스 전투 중 사망한 뒤 다시 2보스에 도달하면, 처치 전 대화는 재도달 기준으로 처리한다.
- 3보스 쌍둥이 보스 전투 중 사망한 뒤 다시 3보스에 도달하면, 쌍둥이 보스 처치 전 대화는 재도달 기준으로 처리한다.

## 2. 처치 후 대화

처치 후 대화는 보스 처치 후 기준을 사용한다.

즉, 해당 처치 후 대화를 실제로 본 적이 있는지를 별도로 판단한다.

예시:

- 1보스 전투 중 사망했더라도, 아직 `Stage1_Boss_Passed_1`, `Stage1_Boss_Passed_2`를 본 적이 없다면 1보스 처치 시 해당 처치 후 대화는 최초 대화로 출력한다.
- 2보스 전투 중 사망했더라도, 아직 `Stage2_Boss_Passed`를 본 적이 없다면 2보스 처치 시 `Stage2_Boss_Passed`는 최초 대화로 출력한다.
- 3보스 쌍둥이 보스 전투 중 사망했더라도, 아직 `Stage3_Stage3_FinalBoss`를 본 적이 없다면 쌍둥이 보스 처치 후 해당 대화를 출력한다.
- 3보스 최종 보스 전투 중 사망했더라도, 아직 `Ending_Arrival`을 본 적이 없다면 최종 보스 처치 후 해당 대화를 출력한다.

# 해결 방안

## 1. 최초도달 기준을 하나 더 만들지 말고, 도달 키를 더 세분화한다

현재 `GameServices.ConsumeFirstScenarioArrival(string scenarioKey, object context = null)`는 특정 키가 처음 소비되는지 확인하고 기록하는 역할을 한다.

이 계약은 그대로 사용할 수 있다.

다만 보스 처치 후 대화에는 시나리오 진입 키와 다른 별도 키를 사용한다.

예시 키:

```csharp
Stage1Boss:Passed
Stage2Boss:Passed
Stage3Boss:FinalBossContact
Stage3Boss:Ending
```

이렇게 하면 기존 시나리오 도달 기준과 처치 후 기준을 분리할 수 있다.

## 2. 1보스 적용 방향

`Stage1_Boss_Contact`는 지금처럼 `IsFirstArrival` 기준을 사용한다.

`Stage1_Boss_Passed_1`, `Stage1_Boss_Passed_2`는 하나의 처치 후 대화 묶음으로 보고 별도 키를 소비해서 판단한다.

권장 흐름:

1. `Battle`에서 `StageManager.IsCleared`가 확인된다.
2. `GameServices.ConsumeFirstScenarioArrival("Stage1Boss:Passed", this)`를 호출한다.
3. 처음이면 `Stage1_Boss_Passed_1`로 이동하고, 이어서 `Stage1_Boss_Passed_2`까지 진행한다.
4. 이미 본 적 있으면 현재 재도달 처리처럼 클리어 오브젝트를 활성화하고 시나리오를 종료한다.

이렇게 하면 1보스 전투 중 사망 후 재도달해도, 처치 전 대화는 재도달로 처리되고 처치 후 대화 묶음은 아직 본 적이 없으면 최초로 출력된다.

## 3. 2보스 적용 방향

`Stage2_Boss_Contact`는 지금처럼 `IsFirstArrival` 기준을 사용한다.

`Stage2_Boss_Passed`는 별도 키를 소비해서 판단한다.

권장 흐름:

1. `Battle`에서 `StageManager.IsCleared`가 확인된다.
2. `GameServices.ConsumeFirstScenarioArrival("Stage2Boss:Passed", this)`를 호출한다.
3. 처음이면 `Stage2_Boss_Passed` 대화로 이동한다.
4. 이미 본 적 있으면 현재 재도달 처리처럼 클리어 오브젝트를 활성화하고 시나리오를 종료한다.

이렇게 하면 2보스 전투 중 사망 후 재도달해도, 처치 전 대화는 재도달로 처리되고 처치 후 대화는 아직 본 적이 없으면 최초로 출력된다.

## 4. 3보스 적용 방향

쌍둥이 보스 처치 전 대화는 지금처럼 `IsFirstArrival` 기준을 유지한다.

쌍둥이 보스 처치 후 `Stage3_Stage3_FinalBoss`는 별도 키를 사용한다.

권장 흐름:

1. `Battle_TwinBoss`에서 `FinalBossReady` 상태가 확인된다.
2. `GameServices.ConsumeFirstScenarioArrival("Stage3Boss:FinalBossContact", this)`를 호출한다.
3. 처음이면 `Stage3_Stage3_FinalBoss` 대화로 이동한다.
4. 이미 본 적 있으면 대화를 생략하고 최종 보스 전투 진입 흐름으로 이동한다.

최종 보스 처치 후 `Ending_Arrival`도 별도 키를 사용한다.

권장 흐름:

1. `Battle_FinalBoss`에서 `StageCompleted` 상태가 확인된다.
2. 기존처럼 루비엘 표시, 추적 해제, BGM 정지, `IsGameCleared` 설정 등 처치 후 연출 준비를 수행한다.
3. `GameServices.ConsumeFirstScenarioArrival("Stage3Boss:Ending", this)`를 호출한다.
4. 처음이면 `Ending_Arrival` 대화로 이동한다.
5. 이미 본 적 있으면 엔딩 씬 전환 흐름으로 바로 이동한다.

## 5. 사망/재시작과 기록 초기화 정책

사망 후 재시작과 `옵션 > 게임 재시작`은 처치 후 대화 기록을 초기화하지 않는다.

이유는 기존 `0525-01-Tasks.md`의 정책과 같다.

- 이미 실제로 도달한 지점은 재도달로 유지한다.
- 아직 실제로 도달하지 못한 지점은 이후 처음 도달했을 때 최초로 처리한다.

따라서 보스전 진입 대화 기록과 보스 처치 후 대화 기록은 모두 같은 저장소를 사용하되, 서로 다른 키로 구분한다.

## 6. 구현 시 확인할 점

- 처치 후 대화를 생략하는 재도달 흐름에서도 클리어 오브젝트 활성화, 입력 차단 해제, BGM 처리, 씬 전환 준비 같은 후처리는 빠지면 안 된다.
- `Stage1_Boss_Passed_1`과 `Stage1_Boss_Passed_2`는 하나의 처치 후 대화 묶음으로 함께 출력되거나 함께 생략되어야 한다.
- `Stage3_Stage3_FinalBoss`를 생략하는 경우에도 최종 보스 전투로 정상 진입해야 한다.
- `Ending_Arrival`을 생략하는 경우에도 엔딩 씬으로 정상 전환되어야 한다.
- 새 키 문자열은 오타가 나면 기록이 분리되므로 상수화하는 편이 안전하다.

## 7. 검증 방향

수정 후에는 다음 흐름을 확인한다.

1. 1보스 첫 진입 후 전투 중 사망
   - 재도달 시 처치 전 대화는 재도달 기준으로 처리된다.
   - 이후 첫 처치 시 `Stage1_Boss_Passed_1`, `Stage1_Boss_Passed_2`는 순서대로 출력된다.
2. 1보스 처치 후 대화를 이미 본 뒤 같은 처치 후 흐름에 다시 들어간 경우
   - `Stage1_Boss_Passed_1`, `Stage1_Boss_Passed_2`는 중복 출력되지 않는다.
3. 2보스 첫 진입 후 전투 중 사망
   - 재도달 시 처치 전 대화는 재도달 기준으로 처리된다.
   - 이후 첫 처치 시 `Stage2_Boss_Passed`는 출력된다.
4. 2보스 처치 후 대화를 이미 본 뒤 같은 처치 후 흐름에 다시 들어간 경우
   - `Stage2_Boss_Passed`는 중복 출력되지 않는다.
5. 3보스 쌍둥이 보스 전투 중 사망
   - 재도달 시 쌍둥이 보스 처치 전 대화는 재도달 기준으로 처리된다.
   - 이후 첫 쌍둥이 보스 처치 시 `Stage3_Stage3_FinalBoss`는 출력된다.
6. 3보스 최종 보스 전투 중 사망
   - 이후 첫 최종 보스 처치 시 `Ending_Arrival`은 출력된다.
7. 각 처치 후 대화를 이미 본 경우
   - 해당 처치 후 대화는 중복 출력되지 않고 다음 진행으로 넘어간다.

# 해결

## 1. 구현 내용

1보스, 2보스, 3보스의 처치 후 대화에 시나리오 진입 키와 다른 별도 키를 적용했다.

추가된 처치 후 기준 키는 다음과 같다.

```csharp
Stage1Boss:Passed
Stage2Boss:Passed
Stage3Boss:FinalBossContact
Stage3Boss:Ending
```

`Scenario_Stage1_Boss`는 보스 처치 후 `Stage1Boss:Passed` 키를 소비한다. 처음이면 기존처럼 `Stage1_Boss_Passed_1`, `Stage1_Boss_Passed_2`를 순서대로 출력하고, 이미 본 적이 있으면 클리어 오브젝트를 활성화한 뒤 종료한다.

`Scenario_Stage2_Boss`는 보스 처치 후 `Stage2Boss:Passed` 키를 소비한다. 처음이면 기존처럼 루비엘을 플레이어 근처에 표시한 뒤 `Stage2_Boss_Passed` 대화로 이동하고, 이미 본 적이 있으면 클리어 오브젝트를 활성화한 뒤 종료한다.

`Scenario_Stage3_Boss`는 쌍둥이 보스 처치 후 `Stage3Boss:FinalBossContact` 키를 소비한다. 처음이면 `Stage3_Stage3_FinalBoss` 대화를 출력하고, 이미 본 적이 있으면 최종 보스 BGM을 재생한 뒤 대화를 생략하고 최종 보스 전투로 들어간다.

최종 보스 처치 후에는 `Stage3Boss:Ending` 키를 소비한다. 처음이면 기존처럼 `Ending_Arrival` 대화로 이동하고, 이미 본 적이 있으면 대화를 생략하고 엔딩 씬 전환을 바로 수행한다.
