# [해결] 0526 직접 씬 전환 경로 진행 보존 정책

작성일: 2026-05-26

---

# 현재 상황

`LevelManager.LoadNextScene()`을 통하는 일반 스테이지 이동은 씬 로드 전에 `Player.PersistCurrentPlayerProgress()`를 호출한다.

하지만 프로젝트에는 `GameServices.ChangeScene()` 또는 `SceneManager.LoadScene()`을 직접 호출하는 경로도 있다. 이 경로들은 호출 목적이 서로 다르기 때문에, 모두 같은 방식으로 플레이어 진행 상태를 저장하면 안 된다.

정책은 다음과 같이 정리한다.

- 플레이어가 죽지 않은 일반 진행 전환에서는 최대 체력 증가를 포함한 런타임 플레이어 진행을 보존한다.
- 사망 후 재시작, 타이틀에서 새 게임 시작, 최종보스 처치 후 엔딩까지 본 완전 클리어 이후 재시작은 완전 초기화한다.
- 타이틀, 엔딩, 레거시 테스트용 직접 로드는 게임플레이 진행 보존 정책 대상에서 분리한다.

---

# 전환 경로 분류

## 1. 진행 유지 경로

살아있는 플레이어가 게임플레이 중 다음 씬으로 이동하는 경로다.

대표 경로는 다음과 같다.

- `LevelManager.LoadNextScene()`
- `Portal`의 일반 다음 레벨 이동
- `Portal`의 지정 씬 이동 중 플레이를 이어가는 용도
- 최종보스 처치 후 엔딩 씬으로 넘어가는 전환

이 경로에서는 플레이어가 살아 있으면 씬 로드 전에 현재 `PlayerStats`, 현재 체력, 궁극기 게이지를 저장한다.

## 2. 완전 초기화 경로

이전 런의 최대 체력 증가, 스킬 보유 상태, 기타 플레이어 진행을 다음 런으로 가져가면 안 되는 경로다.

대표 경로는 다음과 같다.

- 플레이어 사망 후 첫 씬으로 재시작
- 옵션 UI의 게임 재시작
- 타이틀에서 새 게임 시작
- 최종보스 처치 후 엔딩까지 본 뒤 타이틀로 돌아가 새 게임을 시작하는 흐름

이 경로에서는 씬 전환 전에 저장된 플레이어 진행 상태와 스킬 로드아웃을 명시적으로 비우고, `LevelManager`가 존재하면 런 진행 상태도 함께 초기화한다.

## 3. 비게임플레이/레거시 경로

현재 런 진행 보존 정책을 적용하지 않는 경로다.

대표 경로는 다음과 같다.

- 타이틀 UI 내부 전환
- 엔딩/기록 해금 표시용 씬 전환
- `Assets/Scripts/Legacy` 아래의 직접 `SceneManager.LoadScene()` 호출

레거시 스크립트는 현재 게임플레이 플로우의 기준 경로가 아니므로 이번 수정 대상에서 제외한다.

# 원인 정리

직접 씬 전환 경로에서 문제가 되는 지점은 두 가지다.

1. 진행 유지가 필요한 직접 전환에서 `Player.PersistCurrentPlayerProgress()`가 호출되지 않으면, 증가한 최대 체력 같은 런타임 스탯이 다음 씬으로 이어지지 않을 수 있다.
2. 반대로 초기화가 필요한 전환에서 플레이어 파괴 시 `OnDestroy()` 저장이 다시 실행되면, 사망하거나 클리어한 런의 상태가 새 런으로 새어 들어갈 수 있다.

따라서 저장 호출을 단순히 늘리는 것이 아니라, 저장 가능 조건과 전환 목적을 함께 분리해야 한다.

# 구현 내용

## 1. 플레이어 진행 저장 방어

`Assets/Scripts/Actors/PlayerSystem/Player.cs`에 `TryPersistCurrentPlayerProgress()`를 추가했다.

이 메서드는 다음 조건을 만족할 때만 저장한다.

- 현재 씬에서 `Player`를 찾을 수 있다.
- 저장이 활성화되어 있다.
- `PlayerHealth`가 유효하다.
- 플레이어가 살아 있다.

기존 `PersistCurrentPlayerProgress()`는 호환성을 위해 남기되, 내부에서 새 try 메서드를 호출하도록 변경했다.

또한 `OnDestroy()`에서도 같은 조건을 사용해, 죽은 플레이어 상태가 우발적으로 저장되지 않도록 했다.

## 2. `GameServices.ChangeScene()` 보존 옵션 추가

`GameServices.ChangeScene()`과 `GameManager.ChangeScene()`에 `preservePlayerProgress` 옵션을 추가했다.

```csharp
ChangeScene(string sceneName, object context = null, bool preservePlayerProgress = true)
```

동작은 다음과 같다.

- `preservePlayerProgress == true`: 살아있는 플레이어가 있으면 씬 전환 전에 진행 상태를 저장한다.
- `preservePlayerProgress == false`: `LevelManager.ResetState()`로 런 진행 상태를 초기화한 뒤 씬을 전환한다. `LevelManager`가 없으면 저장된 플레이어 진행과 스킬 로드아웃만 직접 비운다.

## 3. 호출부 정책 적용

다음 호출부는 완전 초기화 전환으로 명시했다.

- `GameManager`의 사망 처리 후 `_firstSceneName` 또는 `_unlockSceneName` 이동
- `Game.Title.Menu.ToPlay()`의 새 게임 시작
- `RecordUnlockedStageManager`에서 완전 클리어 후 `Title` 이동

그 외 일반 `ChangeScene()` 호출은 기본값인 `preservePlayerProgress: true`를 유지한다.

# 변경 후 동작

## 일반 진행

플레이어가 살아 있는 상태에서 다음 씬으로 이동하면 현재 런의 플레이어 진행이 저장된다.

예를 들어 최대 체력 100 상태에서 유물로 최대 체력이 120이 된 뒤 다음 씬으로 이동하면, 새 씬에서도 `PlayerStats`가 복원되어 최대 체력과 체력바 증가분이 유지된다.

## 사망/재시작

플레이어가 사망하거나 옵션에서 게임 재시작을 선택하면 기존처럼 런 상태를 초기화한다.

죽은 플레이어의 `OnDestroy()`가 호출되어도 저장 조건에서 제외되므로, 사망 직전 상태가 다시 저장되지 않는다.

## 완전 클리어 후 재시작

최종보스를 쓰러뜨리고 엔딩까지 본 뒤 타이틀로 돌아가는 경우에는 저장된 플레이어 진행을 비운다.

따라서 이후 타이틀에서 새 게임을 시작하면 이전 런의 최대 체력 증가나 스킬 상태를 가져오지 않고 완전 초기 상태로 시작한다.

확인 시나리오는 다음과 같다.

# 주의점

이번 수정은 현재 런의 플레이어 진행 저장 정책을 정리한 것이다.

영구 성장 시스템처럼 런을 넘어 유지되어야 하는 별도 진행이 추가되면, `Player.ClearPersistedProgress()`와 스킬 로드아웃 초기화 대상에 포함시키면 안 된다. 그런 데이터는 별도의 영구 저장 계층에서 관리해야 한다.
