# 현재 구조

`Cerberus`의 `AmbushAttack` 액션은 다음 순서로 진행된다.

1. `ShowIndicator()`로 전역 경고 인디케이터를 표시한다.
2. 2초 대기 후 `AmbushAttackOut` 애니메이션을 재생한다.
3. `_ambushReadyTime`만큼 대기한다.
4. `AmbushAttackIn` 애니메이션을 재생한다.
5. 0.4초 뒤 `ShowSmokeEffect()`와 `AttackWithWeapon`을 실행한다.
6. `Idle` 애니메이션으로 돌아간다.

`AmbushAttackOut.anim`은 `SpriteRenderer.m_Enabled`를 끄는 키를 가진다.

- `time: 0`에서 `m_Enabled = true`
- `time: 0.25`에서 `m_Enabled = false`
- 클립 종료 시간도 `0.25`

`PlayAnimation`은 `MonsterAnimationPlayer`의 타이머 콜백으로 애니메이션 종료를 판단하고, 종료 시 `AnimationPlayer.Stop()`을 호출한다. 이때 `Stop()`은 Animator를 비활성화한다.

---

# 원인 추정

가장 유력한 원인은 `AmbushAttackOut.anim`의 마지막 키프레임과 애니메이션 종료 판정이 같은 시각에 붙어 있는 것이다.

빌드에서는 프레임 타이밍에 따라 다음 순서가 발생할 수 있다.

1. `AmbushAttackOut` 클립이 끝났다고 타이머가 판단한다.
2. `PlayAnimation`이 완료 처리되며 `AnimationPlayer.Stop()`으로 Animator를 끈다.
3. 같은 시각에 있는 `SpriteRenderer.m_Enabled = false` 마지막 키가 샘플되지 않는다.
4. 결과적으로 켈베로스 스프라이트가 완전히 꺼지지 않은 상태로 남을 수 있다.

보조 후보:

- `ShowIndicator()`와 `ShowSmokeEffect()`가 생성한 복제본은 5초 타이머로 파괴되므로, 이번 현상의 주 원인일 가능성은 낮다.
- 빌드에서는 `Monster.Awake()`의 `#if !UNITY_EDITOR` 처리로 디버그 스탯이 꺼지지만, 현재 일반/디버그 스탯의 `AttackCooltime` 값은 동일하므로 기습 숨김 실패의 직접 원인으로 보긴 어렵다.

# 선택 방향

숨김 상태를 애니메이션 마지막 프레임에만 맡기지 않고, 액션 코드에서 명시적으로 보장한다.

선택 이유:

1. 빌드 프레임 타이밍에 영향을 덜 받는다.
2. `AmbushAttackOut` 클립 길이와 키 위치를 조정하는 것보다 의도가 코드에 분명히 남는다.
3. `AmbushAttackIn` 시작 시 다시 보이게 하는 복구 지점을 함께 둘 수 있어 다음 액션으로 상태가 새지 않는다.

# 수정 계획

## 1. 켈베로스 표시 상태 제어 메서드 추가

`Cerberus` 내부에 스프라이트 표시 상태를 명시적으로 제어하는 private 메서드를 둔다.

예상 형태:

```csharp
private void SetBodyVisible(bool visible)
{
    SpriteRenderer.enabled = visible;
}
```

필요하면 현재 본체 `SpriteRenderer` 외에 자식 렌더러가 있는지 확인한 뒤 범위를 넓힌다.

## 2. `AmbushAttackOut` 완료 직후 숨김 보장

`AmbushAttack` 액션에서 `AmbushAttackOut` 애니메이션이 완료된 뒤 `SetBodyVisible(false)`를 호출한다.

예상 위치:

- `AmbushAttackOut` 이후
- `_ambushReadyTime` 대기 전에 실행

이렇게 하면 `AmbushAttackOut.anim`의 마지막 키가 샘플되지 않아도 본체가 확실히 숨겨진다.

## 3. `AmbushAttackIn` 시작 직전 표시 복구

`AmbushAttackIn` 애니메이션을 시작하기 전에 `SetBodyVisible(true)`를 호출한다.

이렇게 하면 숨김 상태가 다음 등장 애니메이션 또는 이후 `Idle` 상태로 새지 않는다.

## 4. 인터럽트와 사망 흐름 확인

기습 중 피격, 사망, 액션 중단이 가능한지 확인한다.

확인 결과 필요하면 다음 보강을 추가한다.

- `Idle`, `Dead`, `Hit` 진입 전 표시 상태 복구
- `MonsterActionController.StopAnimator()`에서 원본 스프라이트 복구와 함께 `SpriteRenderer.enabled = true` 보장

단, 공통 컨트롤러 수정은 다른 몬스터 영향이 있으므로 켈베로스 내부 보정으로 해결 가능한지 먼저 본다.

## 5. 애니메이션 에셋 수정은 보류

`AmbushAttackOut.anim`의 `m_Enabled = false` 키를 종료보다 앞당기거나 클립 길이를 늘리는 방법도 가능하다.

하지만 애니메이션 에셋 수정은 의도가 덜 명확하고 Unity 에디터에서 저장되는 부가 변경이 커질 수 있으므로 1차 선택지로 두지 않는다.

# 적용 결과

`Assets/Scripts/Actors/Monsters/2-6. Cerberus/Cerberus.cs`에 1차 보정을 적용했다.

- `AmbushAttackOut` 완료 뒤 `SetBodyVisible(false)`를 호출해 본체 숨김을 코드로 보장한다.
- `_ambushReadyTime` 대기는 숨김 보정용 0초 딜레이 뒤에 시작되도록 했다.
- `AmbushAttackIn` 시작 전 `SetBodyVisible(true)`를 호출해 본체 표시를 복구한다.
- `AmbushAttackIn` 애니메이션, 사운드, 실제 공격 타이밍은 표시 복구용 0초 딜레이 이후로 연결했다.
- 사망 처리 진입 시 `SetBodyVisible(true)`를 먼저 호출해 숨김 상태가 죽음 흐름으로 새지 않게 했다.

애니메이션 에셋은 수정하지 않았다.

남은 확인은 Unity Editor 플레이 모드와 가능하면 실제 빌드에서 기습덮치기 패턴을 재현하는 것이다.
