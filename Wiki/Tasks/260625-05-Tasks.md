# 범위

`DevotedKnightFragmentShield`가 피격 무효화 횟수를 부여하지만 씬 이동 후 무효화가 반영되지 않는 문제를 확인한 기록이다.

이번 문서는 원인 확인 결과와 수정 방향 기록이다. 이후 실제 코드를 수정한다.

- `Assets/Scripts/Actors/PlayerSystem/Player.cs`

- `Assets/Scripts/Actors/RelicSystem/RelicManager.cs`
- `Assets/ScriptableObject/Relics/007_DevotedKnightFragmentShieldSO.asset`

# 현상

7번 유물 `DevotedKnightFragmentShield`는 피격을 일정 횟수 무효화하는 유물이다.

현재 데이터:

- `baseValue: 1`
- `coinFlipValue: 2`
- `canStack: 1`
- `maxAccumulatedValue: -1`

실제 무효화는 `PlayerHealth.ApplyDamage()`에서 다음 조건으로 처리된다.

```csharp
if (Player.sieldCount > 0)
{
    Player.sieldCount--;
    ...
    return false;
}
```

하지만 기존 `DevotedKnightFragmentShield`는 획득 시점의 현재 플레이어에만 `sieldCount`를 더하고, 현재 플레이어의 `PlayerHealth.OnSieldBreak` 이벤트에만 구독한다.

씬 이동 후 새 플레이어가 생성되면 새 플레이어의 `sieldCount`는 기본값 0이 되고, 새 `PlayerHealth`에도 이벤트 구독이 다시 연결되지 않는다.

---

# 원인

가장 큰 원인은 이전 스킬/원거리/룰렛 문제와 같은 계열이다.

`RelicManager`는 씬 로드 후 새 플레이어를 찾고, 보유 유물 중 `IRelicPlayerRebindHandler` 구현체에 `RebindPlayer(player)`를 호출한다.

하지만 `DevotedKnightFragmentShield`는 `IRelicPlayerRebindHandler`를 구현하지 않는다.

따라서 씬 이동 후 보유 유물은 남아 있어도 새 플레이어의 `sieldCount`와 `OnSieldBreak` 구독이 복원되지 않는다.

추가 주의점:

단순히 씬 이동 때 `RelicManager.GetValueSum(7)`만큼 다시 채우면 이미 사용한 방패 횟수까지 부활할 수 있다.

예를 들어 2회 무효화 유물을 얻고 1회를 사용한 뒤 씬 이동하면 남은 횟수는 1이어야 한다. 총합 기준으로 다시 채우면 2가 되어 버린다.

---

# 수정 방향

남은 방패 횟수를 안전하게 보존하는 방향으로 수정한다.

예상 방향:

1. `Player` 진행 저장 데이터에 현재 `sieldCount`를 포함한다.
2. 씬 이동 시 새 플레이어가 저장된 `sieldCount`를 복원한다.
3. `DevotedKnightFragmentShield`는 `IRelicPlayerRebindHandler`를 구현한다.
4. 재바인딩 시에는 방패 횟수를 다시 더하지 않고, 새 플레이어의 `PlayerHealth.OnSieldBreak` 이벤트 구독만 다시 연결한다.
5. 유물을 잃거나 파괴될 때는 이전 `PlayerHealth` 이벤트 구독을 정리한다.

이렇게 하면 이미 소모한 방패 횟수는 유지되고, 씬 이동 후 남은 횟수만 계속 동작한다.

# 적용 내용

`Assets/Scripts/Actors/PlayerSystem/Player.cs`를 다음 구조로 수정했다.

1. `PersistedPlayerState`에 `SieldCount`를 추가했다.
2. 플레이어 진행 저장 시 현재 `sieldCount`를 함께 저장한다.
3. 새 플레이어가 저장된 진행 상태를 복원할 때 `sieldCount`도 함께 복원한다.
4. 저장/복원 시 음수 값이 들어가지 않도록 `Mathf.Max(0, ...)`로 보정한다.

`Assets/Scripts/Actors/RelicSystem/Relic/DevotedKnightFragmentShield.cs`를 다음 구조로 수정했다.

1. `IRelicPlayerRebindHandler`를 구현해 씬 이동 후 새 플레이어에 다시 바인딩되도록 했다.
2. 획득 시에는 기존처럼 획득한 값만큼 현재 플레이어의 `sieldCount`를 올린다.
3. 재바인딩 시에는 `sieldCount`를 다시 더하지 않는다.
4. 재바인딩 시 새 플레이어의 `PlayerHealth.OnSieldBreak` 이벤트에만 다시 구독한다.
5. 이전 `PlayerHealth` 구독은 새 구독 전, 유물 해제 시, 오브젝트 파괴 시 정리한다.

기대 효과:

- 2회 방패 중 1회를 사용한 뒤 씬 이동하면 남은 1회만 유지된다.
- 2회 방패를 사용하지 않고 씬 이동하면 2회가 유지된다.
- 방패 횟수가 0이 되면 새 플레이어에서도 `OnSieldBreak`가 유물을 제거할 수 있다.
