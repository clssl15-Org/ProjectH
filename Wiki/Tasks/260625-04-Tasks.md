# 범위

`BrassGearOfFate`가 `DamageRoulette.Probabilities`를 바꾸지만 씬 이동 후 효과가 반영되지 않는 문제를 확인한 기록이다.

이번 문서는 원인 확인 결과와 수정 방향 기록이다. 이후 실제 코드를 수정한다.

# 현상

11번 유물 `BrassGearOfFate`는 데미지 룰렛의 고배율 확률을 올리는 유물이다.

현재 데이터:

- `baseValue: 5`
- `coinFlipValue: 10`
- `canStack: 1`
- `maxAccumulatedValue: 20`

기본 룰렛 확률은 다음과 같다.

```text
[22, 30, 25, 15, 6, 2]
```

기존 구현은 `value`만큼 낮은 배율 3칸을 낮추고, 높은 배율 3칸을 올렸다.

```text
[-value, -value, -value, +value, +value, +value]
```

하지만 씬 이동 후 새 플레이어가 생성되면 새 `DamageRoulette`도 기본 확률로 다시 생성되므로, 보유 중인 11번 유물 효과가 다시 적용되지 않을 수 있다.

---

# 원인

가장 큰 원인은 이전 스킬/원거리 보너스 문제와 같은 계열이다.

`RelicManager`는 씬 로드 후 새 플레이어를 찾아 보유 유물 중 `IRelicPlayerRebindHandler` 구현체에 `RebindPlayer(player)`를 호출한다.

하지만 `BrassGearOfFate`는 `IRelicPlayerRebindHandler`를 구현하지 않는다.

따라서 씬 이동 후 새 플레이어의 `DamageRoulette.Probabilities`에는 보유 중인 11번 유물 총합이 다시 적용되지 않는다.

추가 문제:

```csharp
originProb = RelicManager.Instance.player.GetComponent<DamageRoulette>().Probabilities;
int[] newProb = originProb;
```

위 코드는 배열을 복사하지 않고 같은 배열 참조를 공유한다.

그 결과 `newProb`를 수정하면 `originProb`도 같이 바뀐다. 유물을 잃을 때 `originProb`로 되돌려도 이미 수정된 배열을 다시 넣는 셈이라 원상복구가 안전하지 않다.

---

# 수정 방향

`BrassGearOfFate`는 개별 획득 시점 배열을 저장해 되돌리는 방식 대신, 11번 유물의 현재 총합을 기준으로 `DamageRoulette` 확률을 동기화한다.

예상 방향:

1. 기본 룰렛 확률을 고정 기준값으로 둔다.
2. `RelicManager.GetValueSum(11)`로 현재 보유 중인 11번 유물 총합을 계산한다.
3. 총합만큼 낮은 배율 3칸을 낮추고 높은 배율 3칸을 올린 새 배열을 만든다.
4. 씬 이동 후 새 플레이어가 들어오면 새 `DamageRoulette`에 다시 적용한다.
5. 제거 시에는 남은 11번 유물 총합 또는 기본값 기준으로 다시 적용한다.

이렇게 하면 실제 룰렛 확률이 보유 유물 합계와 일치한다.

# 적용 내용

`Assets/Scripts/Actors/RelicSystem/Relic/BrassGearOfFate.cs`를 다음 구조로 수정했다.

1. `IRelicPlayerRebindHandler`를 구현해 씬 이동 후 새 플레이어에 다시 적용되도록 했다.
2. `RelicManager.GetValueSum(data.RelicNumber)`로 11번 유물의 현재 총합을 읽는다.
3. `DamageRoulette.DefaultProbabilities`를 기준으로 새 확률 배열을 계산한다.
4. 낮은 배율 3칸은 총합만큼 낮추고, 높은 배율 3칸은 총합만큼 올린다.
5. 유물 제거 시에는 제거 대상 값을 제외한 총합으로 다시 계산한다.

`Assets/Scripts/Actors/PlayerSystem/DamageRoulette.cs`도 함께 수정했다.

1. 기본 확률 배열을 `defaultProbabilities`로 분리했다.
2. `DefaultProbabilities`는 복사본을 반환하도록 했다.
3. `Probabilities` getter/setter도 배열 복사본을 주고받도록 했다.
4. 잘못된 확률 배열이 들어오면 즉시 예외가 나도록 길이와 null을 검사한다.

기대 효과:

- 씬 이동 후 새 `DamageRoulette`에도 11번 유물 총합이 다시 적용된다.
- `originProb`와 `newProb`가 같은 배열을 공유하던 문제를 제거한다.
- 중첩 획득/제거 후에도 룰렛 확률이 현재 보유 유물 총합과 일치한다.
