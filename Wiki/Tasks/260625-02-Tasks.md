# 현상

1, 2, 3번 스킬 유물은 기본 획득값이 0이고, 동전 앞면 성공 시에만 `coinFlipValue: 10`을 가진다.

의도한 동작은 다음과 같다.

1. 유물 1번은 1번 스킬을 해금하고, 앞면이면 해당 스킬 데미지가 10% 증가한다.
2. 유물 2번은 2번 스킬을 해금하고, 앞면이면 해당 스킬 데미지가 10% 증가한다.
3. 유물 3번은 3번 스킬을 해금하고, 앞면이면 해당 스킬 데미지가 10% 증가한다.
4. 스테이지 이동 후에도 획득한 유물의 효과는 유지되어야 한다.

---

# 현재 구조

`RelicAcquisitionUI`는 동전 결과를 `reinforced` 값으로 계산하고, `RelicManager.AddRelic()`에 그대로 넘긴다.

`RelicManager.AddRelic()`는 `isReinforced`가 `true`이면 `RelicDataSO.CoinFlipValue`를 사용하고, 해당 값을 `Relic.PrepareAcquire()`로 유물 인스턴스에 저장한다.

1, 2, 3번 유물 데이터는 모두 다음 형태이다.

- `baseValue: 0`
- `coinFlipValue: 10`
- `canStack: 0`

각 스킬 유물의 `OnAcquire()`는 현재 플레이어의 `StatesGO`에서 스킬 컴포넌트를 찾고, 해당 스킬의 `BonusMultiplier`에 `value * 0.01f`를 더한다.

현재 적용 위치:

```csharp
firstSkill.BonusMultiplier += value * 0.01f;
player.SkillManager.AddSkill(firstSkill);
```

스킬 사용 시 데미지 계산은 각 스킬 상태에서 `damageRatio * BonusMultiplier * skillPowerMultiplier`를 `Player.CalculateDamage()`로 넘기는 구조이다.

# 확인 결과

동전 앞면 결과가 `AddRelic()`에 전달되지 않는 문제는 아닌 것으로 보인다.

- UI에서 `reinforced`를 계산한다.
- `AddRelic()`에서 앞면이면 `CoinFlipValue`를 선택한다.
- 1, 2, 3번 데이터의 `CoinFlipValue`는 10이다.

또한 플레이어 프리팹 기준 스킬 피해량은 1번 25, 2번 75, 3번 50으로 직렬화되어 있어, 10% 보너스가 단순 정수 버림 때문에 전부 사라지는 상황도 아니다.

가장 유력한 문제는 씬 전환 후 효과 복원 범위이다.

`Player.PersistState()`는 `PlayerStats`를 저장하므로 `skillPowerMultiplier` 같은 스탯 기반 유물은 씬 전환 후에도 유지된다.

반면 1, 2, 3번 유물의 10% 보너스는 `PlayerStats`가 아니라 현재 플레이어 오브젝트 안의 스킬 컴포넌트 `BonusMultiplier`에 직접 붙는다.

`SkillManager.OnDestroy()`는 스킬 목록을 타입 목록으로만 저장한다.

```csharp
_oldStats = skills.Select(s => s.GetType()).ToList();
```

새 씬에서 `SkillManager.Awake()`는 타입으로 스킬을 다시 추가하지만, 이전 플레이어의 스킬 컴포넌트에 붙어 있던 `BonusMultiplier = 1.1` 값은 새 스킬 컴포넌트로 옮겨지지 않는다.

# 원인 추정

가장 유력한 원인은 1, 2, 3번 유물의 앞면 10% 효과가 씬 전환 시 새 플레이어에 재적용되지 않는 것이다.

발생 가능한 순서:

1. 1, 2, 3번 스킬 유물을 동전 앞면으로 획득한다.
2. 현재 플레이어의 해당 스킬 컴포넌트 `BonusMultiplier`가 `1.1`이 된다.
3. 다음 스테이지로 이동하면서 현재 플레이어 진행 상태가 저장된다.
4. `PlayerStats`는 저장되지만, 스킬 컴포넌트의 `BonusMultiplier`는 저장되지 않는다.
5. `SkillManager`는 스킬 타입만 저장한다.
6. 새 씬에서 새 플레이어와 새 스킬 컴포넌트가 생성된다.
7. 스킬 자체는 복원되지만 `BonusMultiplier`는 기본값 `1f`로 남는다.
8. 결과적으로 스킬 해금은 유지되지만 동전 앞면 10% 데미지 증가만 사라진다.

# 수정 방향

`RelicManager`가 씬 로드 후 새 플레이어를 다시 찾는 시점에, 보유 중인 유물 중 플레이어 컴포넌트에 다시 묶어야 하는 유물 효과를 재적용하도록 한다.

1차 수정 범위는 1, 2, 3번 스킬 유물로 제한한다.

선택 이유:

1. `PlayerStats` 기반 유물은 이미 플레이어 진행 상태로 저장되므로 전체 유물에 `OnAcquire()`를 다시 호출하면 효과가 중복 적용될 수 있다.
2. 1, 2, 3번 문제는 `BonusMultiplier`가 플레이어 컴포넌트에 붙어 있어 새 플레이어 생성 시 사라지는 구조가 핵심이다.
3. 스킬 유물별로 새 플레이어 바인딩 시 보너스와 스킬 보유 상태를 복원하면 기존 획득 흐름을 크게 바꾸지 않고 문제를 해결할 수 있다.

예상 방향:

1. `Relic.cs`에 새 플레이어 바인딩 후 재적용이 필요한 유물을 위한 작은 인터페이스를 둔다.
2. `RelicManager.OnSceneLoaded()`에서 새 플레이어를 찾은 뒤 보유 유물 중 해당 인터페이스를 구현한 유물에 재바인딩을 요청한다.
3. 1, 2, 3번 유물은 새 플레이어의 해당 스킬 컴포넌트에 `value * 0.01f` 보너스를 다시 적용한다.
4. 새 씬에서 `SkillManager`가 스킬 타입 복원에 실패한 경우에도, 보유 유물을 기준으로 스킬을 다시 추가할 수 있게 한다.
5. 같은 플레이어에 중복 적용되지 않도록 플레이어 인스턴스 기준으로 적용 여부를 추적한다.

# 추가 원인 추정

`ScoutAccuracyGlasses`는 1, 2, 3번 스킬 유물과 같은 이유로 씬 이동 후 원거리 공격 보너스가 사라질 수 있다.

`KnighthoodLastOathStone`은 더 복합적이다.

1. 체력 조건이 만족되면 `attackPowerMultiplier`와 `RangedAttack.BonusMultiplier`를 함께 2배로 만든다.
2. 씬 이동 시 `attackPowerMultiplier`는 `PlayerStats`에 들어 있으므로 저장될 수 있다.
3. 하지만 `RangedAttack.BonusMultiplier`는 새 플레이어의 새 컴포넌트 기본값으로 돌아간다.
4. 기존 구현은 씬 로드 후 체력 이벤트 구독만 다시 하고, 새 플레이어의 `RangedAttack.BonusMultiplier`에 현재 활성 버프를 다시 적용하지 않는다.

따라서 조건부 버프가 켜진 상태로 씬을 이동하면 공격력 보너스와 원거리 공격 보너스의 유지 상태가 서로 어긋날 수 있다.
