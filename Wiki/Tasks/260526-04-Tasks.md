# 문제 1: 플레이어측 RushStabbing 중복 데미지

플레이어 스킬 `RushStabbing`은 `UpdateBehaviour()`에서 매 프레임 `TakeDamageToEnemy()`를 호출한다.

기존에는 `hitEnemies` 캐시가 주석 처리되어 있어, 히트박스 안에 같은 대상이 계속 남아 있으면 매 프레임 데미지가 들어갈 수 있는 구조였다.

몬스터 쪽 피격 중 데미지 차단을 제거하면 이 문제가 더 크게 드러난다.

- `RushStabbing` 1회 사용 중 같은 몬스터가 여러 프레임 연속으로 데미지를 받을 수 있다.
- 스킬 계수보다 훨씬 높은 데미지가 발생할 수 있다.
- `onEskill` 같은 타격 연동 이벤트가 프레임 단위로 반복 호출될 수 있다.

따라서 몬스터의 데미지 쿨타임을 제거하기 전에, `RushStabbing` 자체에서 같은 사용 회차 안의 중복 타격을 먼저 막아야 했다.

# 문제 2: 몬스터측 피격 중 데미지 차단

몬스터 피격 처리에는 공통 `isInvincible` 플래그는 없지만, 피격 후 일정 시간 동안 재피격을 막는 구조가 섞여 있었다.

- `MonsterStats`에 `_invincibleDuration` 값이 있고, 대부분의 몬스터 스탯 에셋에서 `0.5`로 설정되어 있다.
- `StandaloneHitBrain` 계열 몬스터는 `IsDamaging`이 `true`인 동안 추가 데미지를 무시했다.
- 일반 `Hit` 브레인 계열 몬스터는 현재 액션이 `Hit`이면 다시 `Hit`에 진입하지 못해 재피격 데미지가 막혔다.

따라서 `_invincibleDuration` 값을 0으로 바꾸는 것만으로는 모든 몬스터의 데미지 쿨타임을 제거할 수 없었다.

이번 목표는 피격 연출 길이를 없애는 것이 아니라, 피격 중에도 새 데미지가 즉시 들어가게 하는 것이다. 그래서 `_invincibleDuration` 스탯 값은 유지하고, 데미지 차단 코드만 제거하는 방향으로 정리했다.

# 해결 1: RushStabbing 대상 캐시 복구

`RushStabbing` 1회 사용 중 같은 `IDamageable` 대상에게 데미지가 한 번만 들어가도록 `hitEnemies` 캐시를 복구했다.

적용 내용은 다음과 같다.

- `HashSet<IDamageable> hitEnemies` 필드를 다시 활성화했다.
- `TakeDamageToEnemy()`에서 이미 `hitEnemies`에 들어있는 대상은 `continue`로 건너뛰도록 했다.
- 실제 데미지를 적용하기 직전에 `hitEnemies.Add(damageableObject)`를 호출하도록 했다.
- `ResetSkill()`에서 `hitEnemies.Clear()`를 호출해 스킬 시작마다 이전 대상 캐시를 비우도록 했다.
- `ExitBehaviour()`에서도 `hitEnemies.Clear()`를 호출해 스킬 중단이나 강제 전이 이후에도 캐시가 남지 않도록 했다.

이 변경으로 `RushStabbing`은 1회 사용당 같은 대상에게 한 번만 데미지를 준다. `print(amount)`와 `onEskill?.Invoke()`는 기존 위치를 유지했기 때문에, 실제로 데미지가 들어간 경우에만 실행된다.

# 해결 2: 몬스터 데미지 쿨타임 0

몬스터가 피격 중에도 새 데미지를 즉시 받을 수 있도록 피격 정책을 수정했다.

이번 변경은 `_invincibleDuration` 스탯 값을 0으로 바꾸는 방식이 아니다. 피격 플래시와 `Hit` 연출 시간은 유지하되, 그 시간 동안 데미지 자체가 막히지 않도록 코드 경로를 수정했다.

적용 내용은 다음과 같다.

- 일반 `Hit` 브레인 계열 몬스터는 현재 액션이 `Hit`이어도 새 데미지를 받을 수 있게 했다.
- 일반 `Hit` 브레인 계열 몬스터는 재피격 시 `Hit` 액션을 재시작하도록 했다.
- `StandaloneHitBrain` 계열 몬스터는 `IsDamaging` 중이어도 HP 감소, 데미지 알림, 넉백을 즉시 적용하도록 했다.
- `StandaloneHitBrain` 계열 몬스터가 이미 피격 플래시 중이면 새 데미지 알림은 즉시 완료하고, 피격 플래시 재시작은 강제하지 않도록 했다.
- `StandaloneHitAction`은 재시작 시 기존 플래시 머티리얼을 먼저 복구하고 새 플래시를 시작하도록 했다.
- `StandaloneHitAction.StopAction()`은 실행 중일 때만 콜백을 호출하도록 보호해 중복 콜백 가능성을 줄였다.
- `HitFlash`는 일반 `Hit` 액션 재시작 시 기존 플래시가 남아 있어도 새 플래시를 시작할 수 있도록 `allowRestart`를 사용한다.

이 변경으로 몬스터의 데미지 쿨타임은 실질적으로 0이 된다. 다만 스킬 단위 중복 타격 제한은 각 스킬에서 별도로 관리해야 하며, `RushStabbing`은 해결 1의 변경으로 같은 사용 회차 안에서 같은 대상에게 한 번만 데미지를 준다.
