# 범위

원거리 공격 데미지 증가 유물 효과가 씬 이동 후 기대한 누적 비율로 적용되지 않는 문제를 확인한 기록이다.

보고된 예시는 원거리 공격 데미지가 50% 증가해 12가 되어야 하는 상황에서 10만 나온 케이스이다.

# 현상

플레이어 프리팹 기준 원거리 공격은 다음 계산 구조를 가진다.

```csharp
newProjectile.GetComponent<ProjectileDamage>().Damage =
    (int)(attackPower * damageMultiplier * BonusMultiplier);
```

현재 직렬화값 기준:

- 기본 공격력: 10
- 원거리 공격 `damageMultiplier`: 0.8
- 기본 원거리 공격 데미지: `10 * 0.8 = 8`

`ScoutAccuracyGlasses` 원거리 공격 데미지 증가 누적값이 50%라면 기대값은 다음과 같다.

```text
8 * 1.5 = 12
```

하지만 씬 이동 후 실제 데미지가 10으로 관측되었다.

```text
8 * 1.25 = 10
```

즉, 원거리 공격 보너스 총합 50%가 아니라 일부 값만 `RangedAttack.BonusMultiplier`에 반영된 것으로 보인다.

---

# 현재 구조

`ScoutAccuracyGlasses`는 중첩 가능한 유물이다.

데이터:

- `baseValue: 10`
- `coinFlipValue: 20`
- `canStack: 1`
- `maxAccumulatedValue: 100`

기존 1차 수정에서는 각 `ScoutAccuracyGlasses` 인스턴스가 자기 `value`만큼 새 플레이어의 `RangedAttack.BonusMultiplier`에 더하도록 했다.

```csharp
skill.BonusMultiplier += value * 0.01f;
```

이 방식은 단일 인스턴스에는 충분하지만, 중첩 유물에서는 씬 이동 후 실제 `BonusMultiplier`가 `RelicManager.GetValueSum(9)`와 항상 일치한다는 보장이 약하다.

---

# 원인 추정

가장 유력한 원인은 중첩형 원거리 보너스를 개별 유물 인스턴스의 덧셈 상태로만 관리한 것이다.

발생 가능한 문제:

1. `ScoutAccuracyGlasses` 여러 개가 각각 자기 값만 `RangedAttack.BonusMultiplier`에 더한다.
2. 씬 이동 후 새 플레이어의 `RangedAttack` 컴포넌트가 새로 만들어진다.
3. 보유 유물 재바인딩 과정에서 개별 인스턴스 적용 순서나 런타임 적용 상태가 어긋나면, 실제 `BonusMultiplier`가 누적 합계와 달라질 수 있다.
4. 결과적으로 UI/설명상 누적값은 50%인데 실제 원거리 공격 보너스는 더 낮은 값으로 적용될 수 있다.

원거리 공격의 `attackPower`가 `Player.AttackPower`가 아니라 `Player.playerStats.attackPower`를 직접 읽는 점도 별도 주의 지점이다.

다만 이번 보고의 `8 -> 12` 기대값은 원거리 공격 전용 보너스 50% 기준으로도 설명되므로, 이번 수정 범위는 `ScoutAccuracyGlasses` 누적 보너스 동기화에 둔다.

---

# 수정 방향

`ScoutAccuracyGlasses`는 개별 인스턴스가 각자 값을 더하는 방식 대신, 보유 중인 9번 유물의 총합을 기준으로 현재 플레이어의 원거리 보너스를 동기화한다.

예상 방향:

1. `ScoutAccuracyGlasses` 중 하나를 대표 인스턴스로 둔다.
2. 대표 인스턴스가 `RelicManager.GetValueSum(9)` 기준으로 원거리 보너스 총합을 계산한다.
3. 같은 플레이어에서 누적값이 바뀌면 이전 적용값을 먼저 빼고 새 총합을 다시 더한다.
4. 씬 이동으로 새 플레이어가 들어오면 이전 플레이어 값은 건드리지 않고 새 플레이어의 `RangedAttack.BonusMultiplier`에 총합을 적용한다.
5. 유물 제거 시에도 제거 대상 값을 제외한 총합으로 다시 동기화한다.

이렇게 하면 실제 `RangedAttack.BonusMultiplier`가 보유 유물 합계와 일치한다.

# 적용 내용

`Assets/Scripts/Actors/RelicSystem/Relic/ScoutAccuracyGlasses.cs`를 다음 구조로 수정했다.

1. `ScoutAccuracyGlasses` 중 하나만 대표 인스턴스로 동작한다.
2. 대표 인스턴스는 `RelicManager.GetValueSum(data.RelicNumber)`로 9번 유물의 현재 총합을 읽는다.
3. 같은 플레이어에서 누적값이 바뀌면 이전에 적용한 보너스 총량을 먼저 빼고, 새 총량을 다시 더한다.
4. 씬 이동 후 새 플레이어로 재바인딩되면 새 `RangedAttack` 컴포넌트에 현재 총합을 적용한다.
5. 대표 인스턴스가 제거되면 남아 있는 다음 인스턴스를 대표로 승격한다.
6. 대표가 아닌 인스턴스가 제거되면 대표 인스턴스가 제거 대상 값을 제외한 총합으로 다시 동기화한다.

기대 효과:

- 50% 누적 상태에서는 `RangedAttack.BonusMultiplier`가 `1.5`가 된다.
- 현재 기본 원거리 데미지 `10 * 0.8 = 8` 기준 최종 데미지는 `(int)(8 * 1.5) = 12`가 된다.
- 씬 이동 후에도 보유 유물 총합을 기준으로 새 플레이어의 원거리 보너스가 다시 적용된다.
