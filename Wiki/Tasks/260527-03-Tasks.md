# [조사] 0527 Belia 순간이동 맵 보더 이탈 방지

작성일: 2026-05-27

---

# 범위

`Belia`가 `CurvedAreaAttack` 이후 순간이동하듯 전방으로 이동할 때 벽 너머로 넘어가는 문제를 정리한다.

요구사항은 `Belia.cs`에 추가된 좌/우 맵 보더(`_border_l`, `_border_r`)를 기준으로, 순간이동 후 위치가 보더 바깥으로 나가지 않게 제한하는 것이다.

---

# 현재 구조

관련 코드:

- `Assets/Scripts/Actors/Monsters/3. Bosses/Belia/Belia.cs`
- `Assets/Scripts/Actors/Monsters/3. Bosses/Belia/BeliaAttackBrain.cs`
- `Assets/Scripts/Actors/Monsters/3. Bosses/Belia/BeliaCurvedAreaAttackAction.cs`

`Belia.cs`에는 현재 다음 필드가 추가되어 있다.

- `_border_l`: 좌측 맵 보더
- `_border_r`: 우측 맵 보더

하지만 현재 순간이동 위치 계산에서는 아직 이 값들이 사용되지 않는다.

문제가 되는 이동은 `CurvedAreaAttackEnd` 애니메이션 이후 실행되는 `Do` 컴포넌트 안에 있다.

```csharp
monster.transform.position
    += monster.Direction.ToVector3() * monster._slashMoveDistance;
```

이 처리는 `Transform.position`을 직접 변경하므로 다음 경로를 거치지 않는다.

- 일반 이동의 `TryMove()`
- 물리 충돌에 의한 이동 제한
- 플랫폼 또는 벽 감지 로직

따라서 현재 위치가 보더 근처일 때 `_slashMoveDistance`만큼 더한 목표 위치가 벽 너머가 되어도 그대로 적용될 수 있다.

---

# 원인

원인은 순간이동 목표 위치가 맵 경계로 보정되지 않는 것이다.

`Belia`의 일반 이동이나 대시와 달리, 해당 이동은 짧은 시간에 위치를 직접 대입하는 구조다. 물리 엔진이 중간 경로의 벽을 막아주는 방식이 아니며, 최종 위치가 유효한지 직접 검사해야 한다.

현재 추가된 `_border_l`, `_border_r`는 위치 제한을 위한 데이터로 보이지만, 실제 위치 계산에는 아직 연결되어 있지 않다.

---

# 해결 방안

## 권장안: 순간이동 목표 x 좌표를 보더 범위로 Clamp

순간이동할 목표 위치를 먼저 계산한 뒤, 목표 x 좌표를 좌/우 보더 사이로 제한한다.

개념:

```csharp
var targetPosition =
    monster.transform.position
    + monster.Direction.ToVector3() * monster._slashMoveDistance;

var minX = Mathf.Min(monster._border_l.position.x, monster._border_r.position.x);
var maxX = Mathf.Max(monster._border_l.position.x, monster._border_r.position.x);

targetPosition.x = Mathf.Clamp(targetPosition.x, minX, maxX);
monster.transform.position = targetPosition;
```

이 방식의 장점:

- 기존 공격 브레인과 액션 흐름을 거의 변경하지 않는다.
- 좌/우 보더가 뒤바뀌어 배치되어도 `Min/Max`로 안전하게 처리할 수 있다.
- 문제 지점인 `CurvedAreaAttackEnd` 이동에만 영향을 주므로 변경 범위가 작다.

주의할 점:

- 보더 Transform이 "Belia의 중심점이 도달 가능한 끝"인지, "벽의 실제 위치"인지 기준을 정해야 한다.
- 보더가 벽 위치라면 Belia의 콜라이더 반너비를 고려해야 몸체가 벽에 겹치지 않는다.
- `_border_l` 또는 `_border_r`가 비어 있을 때 어떻게 처리할지 정해야 한다.

---

# 보더 기준 선택

## 1안: 보더를 중심점 제한선으로 사용

`_border_l.position.x`와 `_border_r.position.x`를 Belia의 피벗 또는 중심점이 도달 가능한 최소/최대 x로 본다.

장점:

- 구현이 가장 단순하다.
- 레벨에서 보더 Transform만 원하는 위치로 조정하면 된다.

단점:

- Belia의 피벗이 몸체 중앙이 아니거나 콜라이더가 큰 경우, 시각적으로 벽에 약간 겹칠 수 있다.

## 2안: 보더를 벽 위치로 사용하고 콜라이더 반너비 보정

보더 Transform을 실제 벽 또는 맵 끝 위치로 보고, Belia의 `Collider2D.bounds.extents.x`만큼 안쪽으로 보정한다.

개념:

```csharp
var extentX = monster.Collider.bounds.extents.x;
var minX = leftBorderX + extentX;
var maxX = rightBorderX - extentX;
```

장점:

- 몸체가 벽에 겹치는 상황까지 막을 수 있다.

단점:

- `Monster`에서 사용할 수 있는 콜라이더 참조를 확인해야 한다.
- 보더가 이미 중심점 기준으로 배치된 경우에는 이중 보정이 된다.

현재 요구사항만 보면 1안을 먼저 적용하고, 실제 플레이에서 몸체 겹침이 보이면 2안으로 확장하는 것이 적절하다.

---

# 구현 위치 제안

`Belia.cs`의 `CurvedAreaAttack` 구성 안에서 직접 `transform.position += ...`를 수행하는 부분을 헬퍼 메서드 호출로 바꾸는 방식이 가장 읽기 쉽다.

예상 구조:

```csharp
private Vector3 GetSlashMoveTargetPosition()
{
    var targetPosition =
        transform.position + Direction.ToVector3() * _slashMoveDistance;

    if (!_border_l || !_border_r)
        return targetPosition;

    var minX = Mathf.Min(_border_l.position.x, _border_r.position.x);
    var maxX = Mathf.Max(_border_l.position.x, _border_r.position.x);

    targetPosition.x = Mathf.Clamp(targetPosition.x, minX, maxX);
    return targetPosition;
}
```

사용부:

```csharp
monster.transform.position = monster.GetSlashMoveTargetPosition();
```

보더를 필수 설정으로 볼 경우에는 `Awake()`에서 누락을 바로 감지하는 편이 좋다.

```csharp
if (!_border_l || !_border_r)
    throw new InvalidOperationException(
        $"{nameof(Belia)}은(는) 좌/우 보더를 가지고 있어야 합니다.");
```

다만 기존 씬이나 테스트 프리팹에서 아직 보더가 연결되지 않은 상태가 있을 수 있으므로, 바로 예외를 던질지 경고만 남길지는 프리팹 적용 상태를 확인한 뒤 결정하는 것이 안전하다.

# 결론

이번 문제는 순간이동성 위치 변경이 물리 이동이나 벽 감지를 거치지 않고, 목표 위치를 그대로 적용하기 때문에 발생한다.

가장 작은 수정은 `CurvedAreaAttackEnd` 이후 이동 목표 위치를 계산할 때 `_border_l`, `_border_r`의 x 범위로 `Mathf.Clamp`하는 것이다. 우선 보더를 Belia 중심점 기준 제한선으로 사용하고, 몸체가 벽에 겹치는 문제가 남으면 콜라이더 반너비 보정을 추가하는 방향이 적절하다.
