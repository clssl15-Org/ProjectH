# [확인 결과] 0618 동전 던지기 효과음 최초 재생 누락

작성일: 2026-06-18

---

# 범위

유물 획득 UI에서 동전 던지기 효과음이 처음에는 들리지 않고, 플레이어 사망 후 부활하면 들린다는 제보를 확인한 기록이다.

이번 문서는 원인 확인 결과와 수정 방향 기록이다. 실제 코드, 프리팹, 오디오 에셋 수정은 별도 지시 후 진행한다.

---

# 현상

유물 획득 화면에서 동전을 던질 때 `CoinThrow`, `CoinDrop` 효과음이 최초 진입 흐름에서는 들리지 않는 것으로 보고되었다.

반면 부활 후 첫 씬을 다시 로드하면 동전 던지기 효과음이 정상적으로 들린다고 한다.

관련 구현:

- `Assets/Scripts/UI/Views/RelicAcquisitionUI.cs`
- `Assets/Scripts/Game/Stage/StageManager.cs`
- `Assets/Scripts/Game/Manager/GameManager.cs`
- `Assets/Scripts/Sound/SfxPlayManager.cs`
- `Assets/Scripts/Sound/AudioPlayManager.cs`
- `Assets/Prefab/Game/Game Manager.prefab`
- `Assets/Prefab/Game/Sounds.prefab`

---

# 현재 구조

`RelicAcquisitionUI`는 동전 던지기 흐름에서 직접 효과음을 재생하지 않는다.

- 실제로 동전을 던지는 순간 `CoinThrown` 이벤트를 발생시킨다.
- 동전 낙하 타이밍에는 `CoinDropped` 이벤트를 발생시킨다.
- `StageManager.Start()`가 `RelicAcquisitionUI.CoinThrown` / `CoinDropped`에 SFX 재생 람다를 연결한다.

현재 연결 위치:

```csharp
if (_sfxPlayManager)
{
    RelicAcquisitionUI.CoinThrown += () => _sfxPlayManager.Play(SfxName.CoinThrow);
    RelicAcquisitionUI.CoinDropped += () => _sfxPlayManager.Play(SfxName.CoinDrop);
}
```

`StageManager`는 `_sfxPlayManager`가 비어 있으면 `FindAnyObjectByType<SfxPlayManager>(FindObjectsInactive.Include)`로 씬에서 찾는다.

`Game Manager`는 `DontDestroyOnLoad`로 유지된다. 정상 플레이 흐름에서는 Title 씬의 `Game Manager`가 살아남은 상태로 `Stage0 0` 씬에 진입하고, `Stage0 0` 씬에도 별도 `Game Manager` prefab 인스턴스가 있다. 중복 `GameManager`는 `Awake()`에서 `Destroy(gameObject)`로 제거된다.

# 확인 결과

`RelicAcquisitionUI`의 이벤트 발행 자체는 정상으로 보인다.

- `CoinThrown`은 실제 동전 애니메이션 재생 시작 직후 호출된다.
- `CoinDropped`는 코인 영상 길이와 `_dropEventNotifyTiming`을 기준으로 타이머를 걸어 호출된다.

`Sounds.prefab`의 SFX 목록도 누락은 아니다.

- `SfxName.CoinThrow` 값은 6이고, `Sounds.prefab`의 `Name: 6`에 `79 CoinThrow.wav`가 등록되어 있다.
- `SfxName.CoinDrop` 값은 7이고, `Sounds.prefab`의 `Name: 7`에 `80 CoinDrop.wav`가 등록되어 있다.

따라서 현재 1차 의심점은 클립 누락이 아니라 `StageManager`가 어떤 `SfxPlayManager` 인스턴스를 잡는지이다.

# 원인 추정

가장 유력한 원인은 `StageManager`가 곧 파괴될 중복 `Game Manager` 쪽 `SfxPlayManager`를 잡을 수 있는 구조이다.

발생 가능한 순서:

1. Title 씬의 `Game Manager`가 `DontDestroyOnLoad` 상태로 유지된다.
2. `Stage0 0` 씬이 로드되며 씬 안의 새 `Game Manager` prefab도 생성된다.
3. 새 `GameManager.Awake()`는 기존 인스턴스를 발견하고 `Destroy(gameObject)`를 호출한다.
4. Unity의 `Destroy()`는 즉시 완전 제거가 아니라 프레임 끝에 처리된다.
5. 같은 초기화 구간에서 `StageManager.Start()`가 `FindAnyObjectByType<SfxPlayManager>()`를 호출한다.
6. 이때 살아남을 Title 쪽 SFX가 아니라 곧 파괴될 Stage0 쪽 SFX를 잡을 수 있다.
7. `RelicAcquisitionUI.CoinThrown` / `CoinDropped` 이벤트는 죽은 SFX 매니저를 캡처한 람다에 연결된다.
8. 첫 획득 UI에서는 효과음이 재생되지 않는다.
9. 사망 후 부활로 첫 씬을 다시 로드하면 초기화 순서나 검색 대상이 달라져 살아 있는 SFX 매니저가 잡히면서 효과음이 들릴 수 있다.

보조 후보:

- `79 CoinThrow.wav`, `80 CoinDrop.wav`의 `preloadAudioData`가 꺼져 있다.
- 코드에서 `AudioClip.LoadAudioData()`를 따로 호출하지 않고 `PlayOneShot()`을 바로 호출한다.
- 다만 다른 SFX도 대부분 `preloadAudioData: 0`이므로, 이것만으로 "코인만 최초에 안 들리고 부활 후 들림"을 설명하기에는 약하다.

# 수정 방향

`StageManager`에서 `FindAnyObjectByType<SfxPlayManager>()`에 의존하지 않고, `SfxPlayManager`를 주입받는 구조로 바꾸는 쪽이 안전하다.

선택 이유:

1. `Game Manager` 중복 제거 타이밍에 영향을 받지 않는다.
2. `Scenario_Stage0`, `SettingsUI`처럼 이미 `IInjectable<SfxPlayManager>`를 쓰는 코드와 방향이 맞다.
3. 이벤트 람다가 잘못된 SFX 인스턴스를 캡처하는 문제를 구조적으로 줄일 수 있다.

예상 방향:

1. `StageManager`가 `IInjectable<SfxPlayManager>`를 구현한다.
2. 주입 메서드에서 `_sfxPlayManager`를 설정한다.
3. `AutoBindDependenciesInScene()`의 `FindAnyObjectByType<SfxPlayManager>()` fallback은 제거하거나, 주입 실패 시 경고용 보조 경로로만 둔다.
4. `RelicAcquisitionUI` 이벤트 연결은 주입된 `_sfxPlayManager` 기준으로 유지한다.

보조 확인:

- 주입 수정 후에도 첫 재생 누락이 남으면 `CoinThrow`, `CoinDrop` 클립의 preload 설정 또는 `AudioPlayManager` 초기화 시 `LoadAudioData()` 호출을 검토한다.

의도:

- Title 씬에서 유지되는 `Game Manager`의 `SfxPlayManager`가 씬 로드 주입을 통해 `StageManager`에 전달된다.
- `StageManager.Awake()`에서 임시로 다른 SFX 매니저를 찾더라도, `Start()`에서 코인 이벤트를 연결하기 전에 주입된 SFX 매니저로 덮어쓴다.
- Stage0 씬을 단독으로 플레이하는 경우에는 기존 fallback이 계속 동작한다.

남은 수동 확인:

- Title 씬에서 플레이 시작 후 첫 유물 상자를 열어 `CoinThrow`, `CoinDrop` 효과음이 들리는지 확인한다.
- 플레이어 사망 후 부활한 뒤에도 같은 효과음이 계속 들리는지 확인한다.
