# 현재 상황

씬이 바뀔 때 이전 씬에서 유물로 증가한 플레이어의 최대 체력이 유지되지 않는 것처럼 보이는 문제가 있었다.

특히 `SacredProtectionMark`처럼 `playerStats.maxHeathMultiplier`를 변경하는 유물을 획득한 뒤 다음 씬으로 이동하면, 플레이어 내부 수치는 이어지는 것으로 보이지만 체력바 길이가 다시 기본 길이처럼 보일 수 있었다.

확인 대상은 다음 두 가지였다.

- 실제 플레이어 최대 체력 수치가 씬 전환 시 유지되는지
- 수치는 유지되지만 UI 체력바가 새 씬에서 증가분을 잃어버리는지

---

# 현재 구조

## 1. 플레이어 진행 상태 저장

`LevelManager.LoadNextScene()`은 씬을 로드하기 전에 `Player.PersistCurrentPlayerProgress()`를 호출한다.

현재 흐름은 다음과 같다.

1. `LevelManager.MoveNextLevel()` 또는 `LevelManager.LoadNextScene()`이 다음 씬 이름을 결정한다.
2. `LoadNextScene()`에서 `Player.PersistCurrentPlayerProgress()`를 호출한다.
3. 현재 씬의 `Player`가 `PersistState()`를 통해 정적 필드에 상태를 저장한다.
4. 새 씬의 `Player.Awake()`에서 저장된 상태가 있으면 `playerStats`와 현재 체력을 복원한다.

저장되는 플레이어 상태에는 다음 값이 포함된다.

- `PlayerStats Stats`
- `CurrentHealth`
- `UltimateGauge`

따라서 일반적인 `LevelManager` 경로를 통한 씬 전환에서는 `playerStats.maxHeathMultiplier`도 함께 유지된다.

## 2. 최대 체력 증가 유물

`SacredProtectionMark`는 획득 시 다음 순서로 최대 체력을 증가시킨다.

1. 변경 전 `health.MaxHealth`를 `previousMax`로 저장한다.
2. `player.playerStats.maxHeathMultiplier`에 유물 값을 더한다.
3. 변경된 스탯을 `player.playerStats`에 다시 대입한다.
4. `health.NotifyMaxHealthChanged(previousMax)`를 호출한다.

이 경로는 현재 체력 보정과 `PlayerCondition.MaxHealthChanged` 이벤트 전달까지 이어진다.

## 3. 체력바 UI

`PlayerVM.HealthRate`는 플레이어의 현재 체력과 최대 체력을 `HealthRateData`로 전달한다.

기존 `HealthBarUI`는 `Connect()` 직후 처음 받은 `data.MaxHealth`를 `_baseMaxHealth`로 저장하고, 이후 체력바 폭을 다음처럼 계산했다.

```csharp
var width = _originalWidth * Mathf.Max(data.MaxHealth / _baseMaxHealth, 0f);
```

이 방식은 한 씬 안에서 최대 체력이 증가할 때는 동작한다. 처음 연결 시 기준 최대 체력이 100이고, 이후 유물 획득으로 최대 체력이 120이 되면 `120 / 100` 비율로 체력바가 늘어난다.

하지만 새 씬에서는 `HealthBarUI`가 새로 연결된다. 이때 플레이어의 최대 체력이 이미 120으로 복원되어 있으면, 새 UI는 최초 수신값 120을 다시 기준 최대 체력으로 저장한다.

그 결과 체력바 폭 계산은 `120 / 120`이 되어, 실제 최대 체력은 유지되어도 바 길이는 기본 폭처럼 보인다.

# 원인 정리

직접 원인은 플레이어 진행 상태 저장 실패가 아니라 UI 기준값 재설정이다.

`Player.PersistState()`는 `PlayerStats`를 저장하므로 최대 체력 증가 수치 자체는 일반 씬 이동 경로에서 유지된다. 다만 새 씬의 `HealthBarUI`가 증가된 최대 체력을 기준값으로 다시 잡으면서, 증가분이 화면상의 체력바 길이에 반영되지 않았다.

즉, 문제는 다음처럼 정리된다.

- 실제 최대 체력: 저장 및 복원됨
- 체력바 기준 최대 체력: 새 씬에서 현재 최대 체력으로 재설정됨
- 결과: 최대 체력이 유지되어도 체력바 증가분이 사라진 것처럼 보임

# 해결 방향

체력바 폭 계산에 사용할 기준 최대 체력을 UI 내부의 최초 수신값에 맡기지 않고, 플레이어가 가진 원래 기준 최대 체력을 명시적으로 전달하도록 한다.

구현 기준은 다음과 같다.

- `IPlayer`에 `BaseMaxHP`를 추가한다.
- `Player.BaseMaxHP`는 `originStats` 기준의 원래 최대 체력을 반환한다.
- `HealthRateData`에 `BaseMaxHealth`를 추가한다.
- `PlayerVM.HealthRate`는 현재 체력, 현재 최대 체력, 기준 최대 체력을 함께 전달한다.
- `HealthBarUI.SetHealthRate()`는 최초 수신값이 아니라 `data.BaseMaxHealth` 대비 `data.MaxHealth` 비율로 전체 바 폭을 계산한다.

이렇게 하면 새 씬에 진입했을 때도 기준 최대 체력은 100으로 유지되고, 복원된 현재 최대 체력이 120이면 `120 / 100` 비율로 체력바 폭이 유지된다.

# 구현 내용

## 1. `IPlayer` 기준 최대 체력 추가

`Assets/Scripts/Actors/IPlayer.cs`에 다음 속성을 추가했다.

```csharp
int BaseMaxHP { get; }
```

플레이어 UI는 구체 타입인 `Player`가 아니라 `IPlayer`를 통해 접근하므로, UI 데이터 생성에 필요한 기준 최대 체력을 인터페이스에 노출했다.

## 2. `Player` 기준 최대 체력 구현

`Assets/Scripts/Actors/PlayerSystem/Player.cs`에 `BaseMaxHP` 구현을 추가했다.

```csharp
public int BaseMaxHP => originStats != null
    ? Mathf.Max(1, (int)((originStats.maxHealth + originStats.additionalMaxHealth) * originStats.maxHeathMultiplier))
    : MaxHP;
```

기준값은 런타임에 유물로 변경되는 `playerStats`가 아니라 원본 `originStats`를 사용한다.

## 3. `HealthRateData` 기준값 전달

`Assets/Scripts/UI/Data/HealthRateData.cs`에 `BaseMaxHealth`를 추가했다.

기존 생성자 호환성을 유지하기 위해 `HealthRateData(float health, float maxHealth)`는 현재 최대 체력을 기준 최대 체력으로 사용하는 오버로드로 남겼고, 플레이어 UI에서는 새 생성자를 사용하도록 했다.

## 4. `PlayerVM` 데이터 생성 변경

`Assets/Scripts/UI/ViewModels/PlayerVM.cs`에서 체력 데이터 생성 코드를 변경했다.

```csharp
return new(_player.HP, _player.MaxHP, _player.BaseMaxHP);
```

이제 UI는 현재 최대 체력과 기준 최대 체력을 함께 받을 수 있다.

## 5. `HealthBarUI` 폭 계산 변경

`Assets/Scripts/UI/Views/HealthBarUI.cs`에서 `_baseMaxHealth` 캐시를 제거하고, 전달받은 기준 최대 체력을 사용하도록 변경했다.

```csharp
var baseMaxHealth = Mathf.Max(data.BaseMaxHealth, 1f);
var width = _originalWidth * Mathf.Max(data.MaxHealth / baseMaxHealth, 0f);
```

이제 체력바 기준값은 씬마다 새로 연결되는 UI의 최초 수신값에 의존하지 않는다.

# 변경 후 동작

최대 체력 100 상태에서 `SacredProtectionMark`로 최대 체력이 120이 된 뒤 다음 씬으로 이동하면 다음 흐름이 된다.

1. 이전 씬의 `Player.PersistState()`가 증가된 `PlayerStats`를 저장한다.
2. 새 씬의 `Player.Awake()`가 저장된 `PlayerStats`를 복원한다.
3. `PlayerVM.HealthRate`가 `HP`, `MaxHP = 120`, `BaseMaxHP = 100`을 전달한다.
4. `HealthBarUI`가 `120 / 100` 비율로 전체 체력바 폭을 계산한다.

따라서 실제 최대 체력과 화면상의 체력바 증가분이 함께 유지된다.

# 주의점

이번 수정은 일반적인 `LevelManager.LoadNextScene()` 경로의 씬 이동에서 최대 체력바 기준값을 유지하는 처리다.

`GameServices.ChangeScene()` 또는 `SceneManager.LoadScene()`을 직접 호출하는 별도 씬 전환 경로는 `Player.PersistCurrentPlayerProgress()`를 호출하지 않을 수 있다. 그런 경로에서 플레이어 진행 상태 유지가 필요하다면, 별도로 저장 호출을 넣거나 씬 전환 API를 통일해야 한다.

또한 `BaseMaxHP`는 원본 `originStats` 기준이다. 향후 영구 성장 시스템처럼 원본 기준 최대 체력 자체가 런 중간에 바뀌는 구조가 추가되면, 기준 최대 체력의 소스도 함께 재검토해야 한다.
