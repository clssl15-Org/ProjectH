# 현상

대화 중 `F` 키를 누르면 대화창은 계속 켜져 있는데, 플레이어가 닿아 있는 상자나 포션, 포탈 상호작용도 함께 실행되는 것으로 보인다.

의도한 동작은 다음과 같다.

1. 대화 중 `F` 키는 대화 넘김 또는 타이핑 스킵에만 사용한다.
2. 대화 중에는 상자 열기, 포션 사용, 포탈 이동 같은 월드 `F` 상호작용은 실행하지 않는다.
3. 대화가 끝난 뒤에는 기존처럼 `F` 상호작용이 다시 가능해야 한다.

# 현재 구조

`DialogueManager.Play()`는 대화 진행 중 매 프레임 다음 입력을 확인한다.

```csharp
var isPressed = Input.GetMouseButtonDown(0) || Input.GetKeyDown(KeyCode.F);
```

`DialogueManager`는 `IInputLayerSubject`이며, 보스 시나리오는 대화 구간에서 `ScenarioManager.BlockInputs()`를 호출해 `InputHub`에 `ScenarioManager`와 `DialogueManager`를 등록한다.

현재 `InputHub`는 등록된 `IInputLayerSubject`의 `AllowInput`만 제어한다.

반면 상자, 포션, 포탈은 `InputHub` 입력 계층을 통하지 않고 각자의 `Update()`에서 직접 `F` 키를 읽는다.

- `Box.Update()`: 플레이어가 범위 안에 있고 `F`를 누르면 `OpenBox()`
- `Potion.Update()`: 플레이어가 범위 안에 있고 `F`를 누르면 `Apply()`
- `Portal.Update()`: 플레이어가 범위 안에 있고 `F`를 누르면 다음 씬 이동

따라서 대화 중 `InputHub`가 플레이어 입력을 막아도, `InputHub`에 등록되지 않은 월드 상호작용 오브젝트는 같은 `F` 입력을 계속 처리할 수 있다.

---

# 원인 추정

가장 유력한 원인은 `F` 키의 역할이 두 입력 경로에 동시에 걸려 있는 것이다.

1. 보스 시나리오가 대화 구간에 `BlockInputs()`를 호출한다.
2. `DialogueManager`는 `InputHub` 안에서 살아 있는 입력 주체가 되어 `F` 입력으로 대화를 넘긴다.
3. 같은 프레임에 `Box`, `Potion`, `Portal`도 직접 `Input.GetKeyDown(KeyCode.F)`를 확인한다.
4. 플레이어가 상호작용 범위 안에 있으면 대화 넘김과 월드 상호작용이 동시에 실행될 수 있다.

즉, 현재 문제는 대화 UI 자체보다 `F` 월드 상호작용이 입력 차단 계층 밖에 있는 구조에서 발생한다.

---

# 선택 방향

1차 수정은 보스 씬의 대화 구간에서 월드 `F` 상호작용만 차단하는 방향으로 잡는다.

대화 넘김 입력은 유지한다.

선택 이유:

1. 사용자가 보고한 문제는 대화 중 월드 상호작용이 새는 현상이다.
2. `DialogueManager`의 `F` 입력을 제거하면 기존 대화 진행 방식이 바뀐다.
3. `Box`, `Potion`, `Portal`의 직접 입력 처리를 그대로 두면 `InputHub.Block()`만으로는 해결되지 않는다.
4. 보스 씬에서 먼저 검증한 뒤, 필요하면 일반 스테이지 대화에도 같은 정책을 확장할 수 있다.

장기적으로는 모든 월드 `F` 상호작용을 `InputHub` 계층으로 올리는 것이 더 정돈된 방향이다.

다만 1차 수정에서는 보스 씬 증상 해결을 우선하고, 영향 범위를 작게 유지한다.

# 수정 계획

## 1. 월드 F 상호작용 차단 상태 추가

대화 중 월드 상호작용을 막기 위한 공통 차단 상태를 둔다.

예상 형태:

- 요청자 기반으로 차단/해제를 관리한다.
- 하나 이상의 요청자가 차단 중이면 월드 `F` 상호작용을 막는다.
- 씬 전환 또는 시나리오 종료 시 차단 상태가 남지 않도록 정리 지점을 둔다.

예상 API:

```csharp
Block(requester);
Unblock(requester);
IsBlocked;
```

## 2. `Box`, `Potion`, `Portal`의 F 처리 앞에 차단 검사 추가

각 오브젝트의 `Update()`에서 `Input.GetKeyDown(KeyCode.F)`를 처리하기 전에 월드 상호작용 차단 상태를 확인한다.

차단 중이면 다음 동작을 하지 않는다.

- 상자 열기
- 포션 사용
- 포탈 이동

기존 범위 감지, `F` 표시 오브젝트, 상자 잠금 여부는 그대로 유지한다.

## 3. 보스 시나리오 대화 구간에서 차단 요청

우선 보스 시나리오의 대화 구간에만 월드 상호작용 차단을 연결한다.

대상:

- `Scenario_Stage1_Boss`
- `Scenario_Stage2_Boss`
- `Scenario_Stage3_Boss`

`BlockInputs()`를 호출해 대화 입력 계층을 구성하는 시점에 월드 `F` 상호작용도 함께 차단하고, `UnblockInputs()`로 대화 입력을 해제하는 시점에 월드 상호작용 차단도 해제한다.

`Stage3Boss`처럼 대화 없이 타이머 후 바로 다음 전투로 넘어갈 수 있는 분기도 있으므로, 모든 종료 경로에서 해제가 보장되는지 확인한다.

## 4. 대화 종료 후 복구 확인

대화가 끝난 뒤에는 상자, 포션, 포탈이 기존처럼 다시 동작해야 한다.

특히 보스 클리어 후 대화가 끝나면서 상자/포탈이 활성화되는 흐름은 기존 시나리오 순서를 유지한다.

# 보류할 대안

## `DialogueManager`에서 직접 `Box`, `Potion`, `Portal`을 막는 방식

대화 매니저가 월드 오브젝트를 직접 찾거나 제어하는 방식은 선택하지 않는다.

대화 시스템이 상자, 포션, 포탈의 존재를 알아야 하므로 책임이 섞인다.

## `F` 대화 넘김 입력 제거

대화 중 `F` 입력 자체를 제거하면 월드 상호작용은 새지 않지만, 기존 대화 조작 방식도 바뀐다.

이번 요구사항은 대화 넘김이 아니라 월드 상호작용을 막는 것이므로 1차 선택지에서 제외한다.

## 모든 월드 상호작용을 즉시 `InputHub`로 이전

가장 깔끔한 구조일 수 있지만 영향 범위가 넓다.

동적 생성 포션, 씬 배치 상자, 포탈, 이후 추가될 상호작용 오브젝트까지 모두 등록/해제 흐름을 맞춰야 하므로 보스 씬 1차 수정 뒤 별도로 검토한다.
